# 서버 추천 로직

중심 담당: 백엔드 검증·AI 추천. 데이터 처리·백엔드 담당과 함께 연결한다.

| 파일 | 역할 |
| --- | --- |
| `engine.py` | 목적별 후보 탐색, 제외·중복·서울 목적지 검사, 경로 조회와 시간 제한 적용, 최대 3곳 선정 |
| `ranking.py` | 이동시간의 분 단위 구간 → 구간 내 전원 주차거리 확인 시 거리 → 장소 ID 사전순 비교 |
| `types.py` | 검증된 장소·경로·등록 주차요약을 전달하는 내부 Candidate |
| `cards.py` | 현재 공통 API 필드로 카드·근거·미확인 상태를 구성 |

연결은 `api/dependencies.py` → `services/recommendations.py` → 이 모듈 순서다. `services/recommendation_adapters.py`가 공통 카카오 클라이언트와 `ParkingNearbyService`를 연결한다. 이 패키지에서 HTTP 응답·별도 설정·SQL·DB 연결을 만들지 않는다. 공개 요청은 기존 `schemas/recommendations.py`의 구조화 계약을 사용한다.

출발지는 서울·인천·경기, 목적지는 서울 좌표로 재검증한다. 음식점·카페는 카카오 분류도 확인하며, 목적마다 결과 수를 강제하지 않는다. 이동시간 제한은 초 단위로 적용한 뒤 정렬한다. 주차는 현재 공개된 정형 시설/출처 자료를 사용하며, 등록 주차거리로 빈자리를 추정하지 않는다. 과거 원문 CITYDATA 조회 저장소는 사용하지 않는다.

후보 탐색은 요청당 합계 3페이지, 경로 조회는 최대 5개 동시 실행, 엔진 처리 제한은 90초다. `excluded_place_ids`를 적용하되 여행별 탐색 진행 상태는 저장하지 않는다. 매 요청 처음부터 탐색하므로 첫 3페이지의 후보를 모두 제외한 이후에는 뒤 페이지로 이어지지 않는다. 탐색을 끝내지 못한 경우 `SEARCH_INCOMPLETE` 경고로 범위를 구분한다. 결과 문맥 토큰·재전송 멱등성·과거 카드 재조회는 아직 연결하지 않았다.

경로 일부 실패 시 유효 ETA 후보만 추천하고, 전부 실패하면 ETA·순위가 없는 일반 후보를 반환한다. 호출 한도·필수 설정 누락은 공통 오류로 전달한다. 주차 조회 실패는 미확인으로 처리하며, 설명 실패나 근거 불일치 시 후보·순위를 유지한 채 `EXPLANATION_FALLBACK`과 서버 기본 설명을 반환한다. AI는 서버가 확인한 근거 문구만 선택하고 후보·순위·수치를 생성하지 않는다.

검증 코드는 [추천 단위 테스트](../../../tests/unit/recommendation/README.md)와 `tests/api/test_recommendation_integration.py`에 있다. 외부 호출·DB 조회를 대체하여 실제 서비스·검증기·엔진 연결을 검사한다.
