# 서버 추천 로직

중심 담당: 백엔드 검증·AI 추천. 데이터 처리·백엔드 담당과 함께 연결한다.

후보 동 선정, 실제 장소 필터, 제외 이력 적용, ETA·주차 근거 비교와 최종 후보 선정을 작성할 위치다. 현재 추천 알고리즘·정책 수치·도메인 타입은 구현하지 않았다.

- 향후 `candidates.py`, `filters.py`, `ranking.py`처럼 책임별로 파일을 나눈다. 파일명은 예시이며 빈 구현을 미리 만들지 않는다.
- API Service가 Repository·외부 클라이언트로 확보한 자료를 전달한다. 후보 확보 과정에서 조회가 필요하면 주입받은 조회 기능을 사용한다.
- 핵심 비교 함수는 고정된 입력으로 시험할 수 있게 작성한다. SQL, 제공처 HTTP 요청, Bedrock 호출을 비교 함수 안에 섞지 않는다.
- `app/modules/ai/`는 조건 해석·설명을 담당한다. 모델이 최종 순위나 확인되지 않은 사실을 만들어 결정하지 않도록 한다.
- `app/services/`는 요청 전체의 연결을 담당하고, 이 패키지는 추천 규칙을 담당한다. 같은 필터·정렬을 두 곳에 중복 구현하지 않는다.
- 형식과 근거는 `app/schemas/`의 합의된 타입을 공유한다. 미정인 지표·종료 조건은 구현 시 해당 담당과 결정한다.

검증 코드는 [추천 단위 테스트](../../../tests/unit/recommendation/README.md), 고정 평가 자료는 [evals](../../../evals/README.md)에 둔다.
