# 추천 엔진·재추천 — 파트 2

## 담당 범위

추천 조건 검증, 후보 선정, 검색 진행, 중복 실행 방지, 동일 후보 경로 재평가와 결과 근거를 담당한다. 파트 1의 조회·SQL·DB·수집과 파트 3의 채팅·결과 문맥 인증·공개 라우터·프론트는 변경하지 않았다.

| 파일 | 역할 |
| --- | --- |
| `engine.py` | 목적/지역별 검색, 남은 후보 재평가, 다음 페이지, 경로 재시도 |
| `ranking.py` | 5분 구간 → 확인된 혼잡도(500m 등록 주차장 한 단계 보정) → 실제 ETA → ID |
| `progress.py` | 여행별 진행·조건 버전·제외 이력·요청 재사용, 단일 프로세스 메모리 |
| `areas.py` | 파트 1에서 제공할 경계·도로·주차 자료를 받아 탐색 동 선택 |
| `types.py` | 내부 후보와 확인된 도착지 주변 도로 근거 필드 |
| `cards.py` | 당시 장소·경로·주차·도로 근거 스냅샷 |
| `PART2_HANDOFF.md` | 호출 예시·정책 제안·연결할 부분·검증 한계 |

기존 `api/dependencies.py` → `services/recommendations.py` → 엔진 연결을 그대로 사용한다. R01 요청 형식을 변경하지 않았다. 이동시간 첫 생략은 제한 없음이며, 목적은 최대 2개다. 출발지는 서울·인천·경기, 목적지는 서울이다. 추천 결과는 합계 최대 3곳이고 목적별 수를 강제로 나누지 않는다.

## 검색과 재추천

미노출 후보의 경로·주차를 먼저 다시 조회한다. 부족하면 목적/지역별 다음 페이지로 이어가며 요청당 검색 3페이지·경로 동시 호출 5개·엔진 90초 제한을 유지한다. 시간 제한은 실제 초로 검사한다. 조건이 바뀌면 검색 진행을 초기화하되 같은 여행의 성공 추천·명시적 제외 ID는 유지한다. 일반 후보는 성공 추천 이력에 추가하지 않는다.

동일 여행·요청 ID·내용은 처리 중에도 직렬화하고 동일 응답을 재사용한다. 내용이 다르면 REQUEST_ID_CONFLICT, 오래된 버전·조건이면 CONTEXT_CONDITIONS_MISMATCH다. 실패 응답도 재사용하므로 실제 재시도는 새 request_id로 요청한다. 응답은 복제본으로 반환하여 후속 처리로 당시 결과가 바뀌지 않는다.

## 순위와 실패

사용자 합의에 따라 분담 문서의 이전 1분 기준 대신 5분 구간을 적용한다. 같은 구간의 혼잡도 원활/서행/정체를 비교하고, 500m 이내 등록 주차장이 확인되면 계산상 한 단계 보정한다. 실제 혼잡도 표시와 주차 빈자리 여부는 바꾸지 않는다. 같으면 실제 ETA, ID순이다. 구간 내 하나라도 혼잡도 미확인이면 구간 전체를 실제 ETA순으로 비교한다.

현재 공통 조회 어댑터는 도로 등급을 제공하지 않아 기본은 확인 불가다. 연동 시 Candidate.congestion, congestion_observed_at, congestion_source가 필요하며 엔진은 원천 시각이 없거나 미래·30분 초과이면 사용하지 않는다. 지역 평균을 개별 도착지 도로 등급으로 옮기지 않는다.

경로 일부 실패 시 성공 ETA만 추천한다. 전부 실패하면 ETA·순위 없는 일반 후보를 반환한다. 성공 경로가 있으나 모두 제한 초과이면 후보 없음이며 실패 상태는 유지한다. 인증·설정·호출 한도 장애는 후보 소진으로 처리하지 않는다. 주차 조회·설명 실패는 유효 후보를 유지한다.

## 상태와 연결 한계

기본 저장은 단일 프로세스 메모리이고 마지막 새 실행 후 30분 유휴 만료다. 서버 재시작 시 사라지므로 새 trip_id로 시작해야 한다. 다중 워커 간 상태 공유·재시작 보존은 지원하지 않는다. 자세한 한도와 인계 포트는 PART2_HANDOFF.md를 참고한다.

후보 동 자료 포트는 구현됐지만 실제 조회 연결은 파트 1·3 인계 대상이다. 미연결 시 출발지 중심 검색과 SEARCH_AREA_DATA_INCOMPLETE 경고를 반환한다. 지역/제공처 한도·이번 요청 예산 소진을 서울 전체 후보 소진으로 표현하지 않는다.

동일 후보 경로 재평가는 RecommendationService.retry_routes 내부 포트로 제공한다. R02 결과 문맥 검증·공개 API 연결은 파트 3 담당이다. 결과 문맥 토큰·과거 카드 조회·채팅 중복 해석은 여기서 구현하지 않는다.
