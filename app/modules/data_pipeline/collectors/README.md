# 수집기 작성 위치

교통·인구·주차의 제공처별 수집 코드를 둔다. `citydata.py`는 도시데이터 요청, `parking.py`는 주차 전체 페이지 수집, `topis.py`는 도로별 교통 요청을 담당한다. 파일 읽기는 명시적인 기준정보 반영 작업의 `official_files.py`로 제한한다.

`collect_parking()`은 `ParkingSnapshot(rows, total, received_at, complete, error_code)`를 반환한다. 중간 페이지 실패·총수 변경·짧은 페이지는 부분 입력으로 명시하고 성공한 행을 유지한다. 일반 페이지 실패 후에는 남은 페이지를 계속 조회하며 인증·한도 오류는 중단한다. 미수집 행을 삭제할지는 수집기가 판단하지 않는다.

서울 공통 JSON·CITYDATA·TOPIS는 HTTP 오류뿐 아니라 본문 `ERROR-500`·`ERROR-600`도 일시 서버 오류로 분류한다. 최대2회 추가 호출하며 인증·한도·일반 입력 오류는 재시도하지 않는다. TOPIS의 추가 호출은 회차 처리기가 전체 호출 간격·동시성 제한 안에서 수행한다.

`topis.py`의 단일 HTTP 호출은 네트워크(`provider_network_error`)·서버5xx(`provider_server_error`)·잘못된 XML(`provider_invalid_xml`)을 구분한다. HTTP401/403과 제공처 인증 코드는 인증 오류, HTTP429와 한도 코드는 한도 오류다. 일시적 통신 오류의 재시도는 `pipelines/topis.py`가 전체 동시성·요청 간격 제한 안에서 담당한다.

`app/clients/`의 통신 기능으로 필요한 전체 페이지·대상을 조회하고 원천 자료·출처·수집 시각·누락을 전달한다. 정규화와 DB 적재는 각각 인접한 `normalizers/`, `pipelines/`로 분리한다. 직접 스케줄러를 시작하지 않는다.

`supplemental.py`는 SGIS·S-DoT를 요청하고, 전국 주차 요청은 `national_parking.py`에 둔다. DB 세션을 받거나 공간 조회·저장을 실행하지 않는다. S-DoT 최근3개 시간대 합계 최대10페이지·1만 행, 전국 주차 기능별 최대5천 행 제한을 유지한다. ITS 수집 진입점과 관련 구형 함수는 제거했다.

`official_files.py`는 공식 TOPIS 도로·ID 매핑 XLSX와 121장소 SHP를 읽는다. 공통 `read_xlsx_rows()`는 열 위치·행 순서를 보존하며 도시데이터 장소 목록과 S-DoT 설치 목록에서도 사용한다. SHP의 좌표계·121개 고유 장소·닫힌 링을 확인하고 모든 링을 전달한다. 도로 ID·정점 순서 등 값 검증은 `normalizers/official_files.py`에서 수행한다.

TOPIS는 각 파일을 한 번 읽은 바이트로 파싱·해시 계산을 수행하고 복사본을 보관하지 않는다. 두 파일의 헤더·파일명·행·SHA-256·바이트 수를 각각 전달한다. 버전과 기준일은 가져오기 인자로 별도 지정하며 파일 해석기가 임의로 연도를 붙이지 않는다.

전국 주차는 세 기능을 각각 수집한다. 필요한 필드·실제 수신 시각·실패/부분/완전 여부만 메모리로 전달하며 한 기능의 실패가 다른 기능을 취소하지 않는다. 잘못된 총수/페이지, 반복 페이지, 조기 빈 페이지, 5페이지 제한은 전체 수집으로 표시하지 않는다.

시설·운영은 호출자가 넘긴 `progress`로 이어받고 현황은 항상 첫 페이지부터 수집한다. 진행 상태 읽기·저장은 파이프라인/저장소가 담당한다. 총수에 못 미친 빈/짧은 마지막 페이지는 다음 회차에도 동일한지 확인하며, 반복 확인 후 새 스캔을 시작해도 전체 수집 성공으로 표시하지 않는다. SGIS 인증·경계 요청은 `https://sgisapi.mods.go.kr/OpenAPI3/`를 사용한다.

S-DoT는 KST 현재 시간대와 직전 2개 시간대를 측정 시각 접두 필터로 조회한다. 시간대별 첫 응답 총수와 각 페이지의 총수·수신 시각·행 수·중복·중도 빈 페이지/실패를 함께 반환한다. `SeoulClient.fetch_page_document()`가 성공 응답의 전체 JSON envelope와 실제 HTTP 수신 시각을 제공하고, 기존 `fetch_page()`의 `(total, rows)` 계약은 유지한다. 중간 실패 전 확보한 행은 버리지 않는다. 시간 접두 필터는 실제 공식 API에서 확인한 동작이며 요청 범위 밖의 행은 채택하지 않는다. 전체 최대10페이지·1만 행이고 기존 HTTP 재시도 포함 최대30회 시도다. 제공처의 정렬에 의존하지 않고 정규화 시 측정 시각·DATE로 선택한다. 여러 요청 사이에 고정된 스냅샷은 보장하지 않는다. `query_complete`는 총수와 받은 행의 일치만 뜻하고 전 이력/전 센서 최신 관측 확보를 뜻하지 않는다. 설치 XLSX는 같은 바이트로 해시와 헤더/행을 읽으며 검토한 해시와 일치할 때만 2025-11-13 기준일과 전체 기준본 표시를 붙인다. 다른 파일의 날짜는 미확인, 전체 기준본 여부는 false다. 관측 조회의 완전성과 설치 기준본의 완전성은 별개다.

도시데이터의 `collect_citydata()`는 `CityDataDocument(body, received_at)`를 반환한다. body는 현재 JSON 봉투이고 received_at은 응답 직후 시각이다. 결과 코드·대상 오류는 `CityDataResponseError`로 전달해 메모리에서 확인하고 짧은 사유만 기록한다. 실제 HTTP에서는 봉투·결과 코드·장소 식별을 검사하며 원문은 파일로 보관하지 않는다.
