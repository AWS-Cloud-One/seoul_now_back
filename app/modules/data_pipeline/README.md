# 데이터 수집·처리

중심 담당: 데이터 처리. API·DB·공간 조회·외부 연결은 백엔드와 공동으로 관리한다.

```text
jobs의 단발 실행
  → collectors: 외부 API·파일 수집
  → pipelines: 회차 처리·검증·트랜잭션 적재
  → repositories/models: 공통 DB 저장과 조회
  → API: 수집된 최신 데이터를 제공
```

서울시 OA-21285 통합 실시간 도시데이터 전체 응답을 파일로 보존하고 DB에는 원문 참조와 정형 값을 적재한다. 유동인구, 도로소통, 대중교통, 주차, 사고·통제, 따릉이, 날씨, 충전소, 행사, 상권 등 제공되는 섹션을 원본 그대로 보존한다. 현재 테이블·관계는 [실행 모델](../../models/), 입력 파일은 [공식 자료 안내](../../../jobs/README.md#공식-입력-자료), 실행 방법은 [jobs 안내](../../../jobs/README.md)를 참고한다.

한 번의 OA-21285 요청은 한 장소를 조회한다. 현재 자동 반복 실행은 별도 worker의 `jobs.scheduler`가 담당한다. API 요청 수와 최신성 요구를 확인하고 장소와 실행 주기를 조정한다. AWS 스케줄 연결은 호출 한도와 주기 합의 후 진행한다.

GetParkInfo는 등록 기본정보를 별도 주차 테이블에 적재하며, OA-21285 통합 스냅샷과 목적이 다르다. 이 데이터가 주차 가능 면수를 보장하지 않는다. 실시간 표식과 원천 시각을 확인해 미제공/지연 상태를 구분한다.

각 계층의 역할:

| 위치 | 역할 |
| --- | --- |
| `collectors/` | 제공처별 요청, 페이지·장소 단위 수집과 응답 구조 확인 |
| `pipelines/` | 한 회차의 잠금·성공/실패 기록·적재 트랜잭션 |
| `normalizers/` | 대상별 필드·좌표계·단위·시각 검증과 변환 |
| `identity.py` | 출처·대상 키 해석, 처리 버전과 지문 생성 |
| `app/repositories/` | 공통 DB 저장과 조회 |
| `app/storage/` | 원문 파일 보관·무결성 확인과 인증정보 제거 |
| `app/models/`·`migrations/` | DB 테이블과 변경 이력 |
| `jobs/` | API와 별도 실행하는 단발 작업 |

정기 수집은 API 요청이나 FastAPI lifespan에서 돌리지 않는다. AWS 담당과 호출 주기·실패/재시도 정책을 합의하고 외부 스케줄러에서 단발 job을 호출한다.
