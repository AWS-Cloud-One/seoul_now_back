# 데이터 수집·처리

중심 담당: 데이터 처리. API·DB·공간 조회·외부 연결은 백엔드와 공동으로 관리한다.

주차·도로·인구의 정형 저장 커밋 후 기존 지도 공개본 갱신까지 연결한다. 위치/형상과 실시간 관측 갱신을 구분하며 공개 실패/보류는 수집 결과와 별도 보고한다. 원자적 공개·재시도와 명령별 범위는 [실행 안내](../../../jobs/README.md#저장-후-지도-공개)를 따른다.

```text
jobs의 단발 실행
  → collectors: 외부 API·파일 수집
  → pipelines: 회차 처리·검증·트랜잭션 적재
  → repositories/models: 공통 DB 저장과 조회
  → API: 수집된 최신 데이터를 제공
```

서울시 OA-21285 통합 실시간 도시데이터 전체 응답을 파일로 보존하고 DB에는 원문 참조와 정형 값을 적재한다. 유동인구, 도로소통, 대중교통, 주차, 사고·통제, 따릉이, 날씨, 충전소, 행사, 상권 등 제공되는 섹션을 원본 그대로 보존한다. 현재 테이블·관계는 [실행 모델](../../models/), 입력 파일은 [공식 자료 안내](../../../jobs/README.md#공식-입력-자료), 실행 방법은 [jobs 안내](../../../jobs/README.md)를 참고한다.

한 번의 OA-21285 요청은 한 장소를 조회한다. 현재 자동 반복 실행은 별도 worker의 `jobs.scheduler`가 담당한다. API 요청 수와 최신성 요구를 확인하고 장소와 실행 주기를 조정한다. AWS 스케줄 연결은 호출 한도와 주기 합의 후 진행한다.

GetParkInfo는 등록 기본정보를 별도 주차 테이블에 적재하며, OA-21285 통합 스냅샷과 목적이 다르다. 이 데이터가 주차 가능 면수를 보장하지 않는다. 실시간 표식과 원천 시각을 확인해 미제공/지연 상태를 구분한다.

서울 등록·시영·도시데이터 주차는 각 원천의 필드명으로 추출한 뒤 공통 요금·조건·운영시간·현황으로 변환한다. B04/B05 코드에서 조건·요금 컬럼, 운영시간 행과 주차 현황의 정형 저장을 연결했다. 정식 0010 구조에 연결되며 기존 0009 DB는 먼저 전환해야 한다. 변환·저장 경계는 [정규화 안내](normalizers/README.md)를 따른다.

각 계층의 역할:

| 위치 | 역할 |
| --- | --- |
| `collectors/` | 제공처별 요청, 페이지·장소 단위 수집과 응답 구조 확인 |
| `pipelines/` | 한 회차의 잠금·성공/실패 기록·적재 트랜잭션 |
| `normalizers/` | 대상별 필드·좌표계·단위·시각 검증과 변환 |
| `identity.py` | 출처·대상 키 해석, 처리 버전과 지문 생성 |
| `results.py` | 처리 범위·집계 단위·채택/거절/중복/충돌 수와 사유, 정규화 후 저장 판단의 공통 표현 |
| `app/repositories/` | 공통 DB 저장과 조회 |
| `app/storage/` | 원문 파일 보관·무결성 확인과 인증정보 제거 |
| `app/models/`·`migrations/` | DB 테이블과 변경 이력 |
| `jobs/` | API와 별도 실행하는 단발 작업 |

정기 수집은 API 요청이나 FastAPI lifespan에서 돌리지 않는다. AWS 담당과 호출 주기·실패/재시도 정책을 합의하고 외부 스케줄러에서 단발 job을 호출한다.

도시데이터 단일 수집 결과는 `unit=section`, `scope=citydata_section_processing`이다. 인구 처리와 주차·도로 입력 준비의 세 항목 상태를 합친 결과이며, 세 분야의 정형 저장 완료 건수가 아니다. 인구의 실제 쓰기는 `sections.population`, 주차의 실제 쓰기는 후속 투영(`unit=row`), 도로 좌표 대조는 공식 파일 가져오기 결과로 구분한다. 응답 전 실패는 received=0, 봉투/대상 오류는 기대한 세 섹션을 모두 거절한다. 세부 보고서는 기존 raw_payloads의 외부 processing_report 파일에 두고 DB JSON 컬럼이나 테이블은 추가하지 않는다.

주차 수집·도시데이터 주차 투영의 집계는 `unit=row`, `scope=parking_normalization`이다. 정확히 같은 선택 값만 중복으로 세며, 충돌은 거절 수에 포함한다. 등록값 충돌·동일 시각 현황 충돌·식별 보류는 원문과 회차 사유를 남기고 기존 행을 유지한다. 부분 입력이나 식별 보류가 있으면 누락 시설을 비활성화하지 않는다. 서로 다른 장소에서 온 투영도 전체 후보의 UUID 대응을 먼저 확인한 뒤 한 트랜잭션으로 쓰며, 각 후보의 원래 payload·수신 시각은 유지한다.

주차 B04 저장은 `parking_source_records`의 조건·요금 컬럼, `parking_operating_hours`, `parking_field_issues`, `parking_availability_latest`로 연결한다. `repositories/parking_state.py`가 반복값과 현황 갱신을 담당한다. 관측과 최근 시도는 서로 다른 시계·payload를 가지며, 수집 행의 `accepted`는 실시간 현황이 사용 가능하다는 의미가 아니다. 소비자는 현황의 `usable`, `observed_at`, `attempt_status`를 함께 확인해야 한다. 동일 시각 충돌·여러 공간의 집계 범위 미확정은 사용을 보류한다.

전국 주차의 요금 시간은 분으로 처리하고 자동 수집은 1시간 간격이다. 관측 시각 없는 빈자리는 DB의 `attempt_*`에 보존하며, `ParkingRepository.availability()`가 수신 후 1시간 이내 값의 활용을 허용한다. 이 내부 조회는 원시 ORM 행 대신 `ParkingAvailability`를 반환하고 출처·가용 수량·시각 기준·만료 시각·사유를 구분한다. DB의 관측 검증 플래그와 조회 시점의 활용 가능 판정은 다르다. 전국 자료라도 집계 범위 충돌, 무효 수량, 시각 누락/미래/만료면 숫자를 반환하지 않는다. 원천 `observed_at`은 NULL로 유지한다.

현재 모델은 0011까지의 34개 테이블이다. 0010의 주차·도로·센서 구조에 TOPIS 최신 시도 상태와 파일 삭제 대기열이 추가됐다. 기존 DB는 백업 후 Alembic head까지 전환하고 새 DB도 같은 경로를 사용한다. 별도 전환 초안과 테스트 전용 DDL 호출은 제거했다.

시영·CITYDATA 빈자리의 내부 조회도 `ParkingRepository.availability()`를 사용한다. 관측 후1시간을 넘거나 최신 제공 상태가 미제공이면 수량을 반환하지 않는다. 마지막 유효 관측은 보존하므로 DB의 `usable`만으로 현재 사용 가능 여부를 판단하지 않는다. SGIS 경계 변경 시 도로↔행정동 관계도 같은 트랜잭션에서 갱신하며, 검증된 완전 목록만 누락 동을 비활성화한다.

TOPIS 도로 소통은 정상 0·일부 결측·전부 무효를 구분한다. 일부 유효 응답은 결측과 함께 한 관측으로 저장하고, 전부 결측/무효이거나 늦게 적재되는 과거 응답은 기존 최신값을 덮지 않는다. 입력별 처리 보고서에 값 품질·원천 시각 미제공·갱신 여부를 분리한다. `unit=response`, `scope=road_traffic_normalization`은 응답 채택 수이며 속도/여행시간 두 필드의 유효 개수는 별도다. B06은 기존 테이블을 사용하며 스키마를 추가하지 않는다.

도로 기준본은 공식 ID 대응의 선형·포함 범위와 CITYDATA 좌표 충돌을 검사한 뒤 교체한다. 검증 자료 부재/부족·불일치는 기존 기준본을 유지하고 원본과 보고서를 보존한다. 현재 보관 표본의 일부 구간은 보류 상태이며, 상세 기준과 실행 결과 해석은 [공식 도로선 가져오기](../../../jobs/README.md#공식-도로선id-매핑)를 따른다.

S-DoT는 설치 기준정보(`pedestrian_sensors`)와 마지막 유효 관측/최근 시도(`pedestrian_sensor_latest`)를 분리한다. 원본 XLSX와 페이지 전체 응답을 보관하고 채택값에서 해당 근거를 찾을 수 있다. 미관측·충돌·시간 역행은 이전 유효값을 덮지 않는다. 설치 수·관측값 보유 수·실제 갱신 수는 별개이며, 소비 시 활성 여부·기준본 해시 일치·관측 시각·최근 시도 상태를 함께 확인한다. 센서 API는 추가하지 않았다.

도시데이터는 전체 응답 봉투와 인구·주차·도로 좌표만 담은 `citydata-selected-v1`을 분리한다. 선택본과 처리 보고서는 가공 시각을 수신 시각으로 쓰지 않으며 원문 부모 참조를 남긴다. 주차 재처리·도로 대조는 선택본을 우선하고, 기존 원문만 있는 자료는 같은 필드 계약으로 읽는다. 이전 유효 섹션 재사용·최신 시도 실패·정상 빈 목록을 구분한다. 원문 삭제나 보존 기간 정책은 추가하지 않았다.
