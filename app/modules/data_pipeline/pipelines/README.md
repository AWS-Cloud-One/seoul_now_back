# 수집·적재 처리

0012 스키마에서 기준정보 반영·각 분야 직접 적재·조회/지도 공개·스케줄러가 정형 DB를 사용한다. 응답 원문·가공본·처리 보고서 파일은 생성하지 않는다.

## 계층과 트랜잭션

- `jobs/`: CLI·설정·HTTP/DB 자원 준비·결과 출력.
- `collectors/`: 외부 요청과 실제 수신 시각 확보. 파일 읽기는 명시적 기준정보 가져오기에서만 수행.
- `normalizers/`: 전달받은 값의 필드 선택·검증·변환. 파일·DB 접근 없음.
- `pipelines/`: 처리 순서·잠금·트랜잭션·실패 집계.
- `app/repositories/`: DB 조회와 정형 저장. 파일 접근 없이 정형 값만 처리.

HTTP 대기 중 DB 쓰기 트랜잭션을 열어두지 않는다. 성공한 부분은 저장하고 실패한 부분은 마지막 정상값을 유지한다. 함께 반영할 변경은 트랜잭션으로 묶고, SQL 실패 시 savepoint 또는 전체 트랜잭션을 롤백한다. 실제 수신 시각·관측 시각을 처리 시각으로 대체하지 않는다. 같은 위치·도형은 공간 컬럼 UPDATE에서 제외한다. API는 별도의 읽기 전용 REPEATABLE READ 세션을 사용한다.

## 직접 적재가 완료된 경로

| 파일 | 처리 범위 |
| --- | --- |
| `official_files.py` | 운영자가 교체한 현재 장소·도로·센서 기준파일의 검증 결과를 DB에 명시적으로 반영 |
| `parking.py` | 서울·시영 주차와 현재 도시데이터의 주차 후보 정형 저장 |
| `national_parking.py` | 전국 시설·운영·현황의 선택 필드와 현재 페이지 진행 상태를 함께 저장 |
| `citydata.py`, `citydata_storage.py` | 현재 장소 응답에서 인구를 저장하고 주차 후보를 메모리로 전달 |
| `sdot.py` | DB 설치정보와 현재 응답으로 마지막 유효 관측·최근 시도를 저장 |
| `boundaries.py` | 현재 SGIS 응답을 공간 검증해 경계·도로 관계를 함께 저장 |
| `topis.py`, `topis_storage.py` | 현재 속도·통행시간·최근 시도·회차 집계를 짧은 DB 배치로 저장 |
| `supplemental.py` | SGIS·S-DoT·전국 주차 수집 자원과 전용 저장 경로 연결 |

이 경로는 응답 원문·선택본·처리 보고서를 파일로 저장하지 않는다. SQL 저장 실패에도 응답을 백업하지 않으며 짧은 실패 기록만 남긴다. 반복 수집은 DB의 활성 장소·도로·센서 설치정보를 사용한다. 기준파일은 명시적인 가져오기 이후 런타임 선행 파일이 아니다.

### 주차

공통 주차 저장은 동일 시설 식별·충돌 판정·요금/운영 정보·관측 상태를 분리해 처리한다. 도시데이터는 현재 회차에서 모은 후보만 비교한다. 후보별 실제 수신 시각을 유지하므로 새 등록정보가 이전 빈자리 관측을 새 값처럼 만들지 않는다. 주차 섹션 누락·무효·빈 목록에서 기존 DB 값은 유지하고 과거 입력은 재처리하지 않는다. 저장된 응답을 읽던 `project_citydata_parking` 명령과 `CityDataRepository`는 제거했다.

전국 주차는 `collection_cursors`와 `collection_cursor_pages`로 현재 스캔의 진행 위치·페이지 지문만 저장한다. 정형 값과 다음 페이지를 같은 트랜잭션으로 반영한다. 실패 페이지부터 다음 회차를 이어가며 오래된 배치는 데이터와 진행 상태 모두 갱신하지 않는다. 완료·교체된 스캔의 지문은 지운다. 수집 로그 보관 여부와 페이지 진행은 독립적이다.

### 인구·도시데이터

응답 봉투·장소 식별을 확인한 뒤 인구·주차의 필요한 필드만 선택한다. 인구는 범위·혼잡도·대체 여부·관측 시각을 각각 검사하며 부분값은 NULL·사유로 표현한다. 0과 미제공은 구분한다. `PopulationWriter`는 실제 수신 시각과 관측 시각의 역행을 막고, 마지막 정상 관측과 최근 시도를 각각 `population_latest`, `population_attempt_latest`에 기록한다.

인구 SQL 실패는 savepoint로 격리해 현재 주차 후보를 처리할 수 있게 한다. 여러 장소의 주차는 메모리에 선택 후보만 모아 회차 종료 시 병합·저장한다. 인증/할당량 오류면 남은 장소 호출을 중단하고 이미 받은 정상 후보는 저장한다. 단일 장소 수집도 인구·주차를 같은 실행 흐름에서 처리한다. 정기 수집에서 도로 좌표를 갱신하지 않으며, 도로 기준정보 반영 시 현재 응답의 ID·좌표만 별도로 조회한다.

### S-DoT·SGIS

S-DoT는 DB 설치 위치·기준 버전을 현재 관측과 대조한다. 정기 관측 수집은 설치정보를 갱신하거나 XLSX를 읽지 않는다. 미관측을0명으로 바꾸지 않으며 유효 관측/최근 시도·관측/수신 시각·DATE 역행과 충돌 판정을 유지한다. 설치 기준 변경은 `import_sensor_locations`에서 수행한다.

SGIS는 행별 savepoint에서 도형을 검사하고 상대 면적 변화0.1% 이내의 유효한 면 도형 복구만 허용한다. 중복/무효 식별·도형은 거절하고 다른 정상 행은 저장한다. 구별 요청 실패도 성공한 구의 자료를 폐기하지 않는다. 불완전한 행정동 목록에서는 기존 누락 행을 비활성화하지 않는다. 채택한 서울·행정동 경계와 도로 교차 관계는 같은 트랜잭션으로 갱신하며 저장 실패 시 함께 롤백한다. 정형 저장/결과에는 원문 `source_input` 복사본을 남기지 않는다.

### TOPIS

전체 활성 도로·10분 주기·최대8개 동시 요청·0.05초 요청 간격·도로별 제한 재시도 정책은 유지한다. XML에서 링크 ID·속도·통행시간과 실제 수신 시각만 추출하고 `normalizers/topis.py`에서 검증한다. 버퍼에는 선택한 정형 필드만 넣고 커밋 후에는 값 없는 처리 결과만 회차 집계에 남긴다.

`topis_storage.store_batch()`는 최대50건씩 또는1초가 지나면 버퍼를 저장한다. 관측값·최근 시도·회차 수량/사유별 집계를 같은 트랜잭션으로 반영한다. 도로별 오류는 savepoint로 격리하며, 시도 저장 실패 시 관측만 커밋되지 않게 한다. 회차 집계 실패면 배치 전체를 롤백한다. 최신값은 실제 수신 시각의 역행을 막고 정상0·부분 결측·기존 유효값 보존을 유지한다. 도로선은 갱신하지 않는다.

정상 종료 시 마지막 버퍼를 저장하고 회차를 닫는다. 타이머 저장 중에 마지막 작업이 끝나도 진행 중인 커밋을 취소하지 않는다. 중단 시 커밋된 값과 수량을 유지하고 미커밋 응답은 다음 회차에서 다시 수집한다. 커밋과 취소가 겹치면 DB 수량을 기준으로 종료 상태를 정리하며 버퍼를 재실행하지 않는다. SIGKILL 등으로 종료 상태를 기록하지 못하면 다음 잠금 소유자가 DB의 미종료 회차만 정리한다. 원문 체크포인트·회차 통합·재생·파일 삭제 대기열을 사용하지 않는다.

회차 요약은 최신20회만 유지하며 `road_traffic_latest`와 `road_traffic_attempt_latest`는 로그 삭제와 독립적이다. 과거 도로별 로그에서 시도 정보를 옮기는 처리는0012 이관에 포함하며 런타임 raw 조인을 제거했다. `ReferenceRepository`의 도로 순환 대상 선정도 최근 시도 테이블만 읽는다.

## 조회·회차 기록·실행 설정

지도 공개와 API는 정형 관측·실제 수신 시각·최근 시도만 읽는다. 수집 요약을 조인하거나 원문 파일을 열지 않는다. 갱신 실패·부분값·관측 없음·유효기간 판단과 API 계약을 유지한다. 공개는 별도 트랜잭션이므로 실패해도 정형 저장 성공을 되돌리지 않으며 DB만으로 재공개한다.

출처별 종료된 수집 요약은 최근20회만 유지한다. CITYDATA는 전체 장소 수집과 주차 병합까지1개 회차로 집계하며 수량은 실제 정형 반영과 같은 트랜잭션에서 쓴다. 관측·최근 시도·페이지 진행은 로그 정리와 독립적이다. `maintenance.py`는 수집기와 같은 잠금 아래 중단된 회차를 커밋된 집계로 닫는다. 입력 파일을 재생하지 않는다.

스케줄러는 DB의 장소·도로·경계·센서 설치정보를 선행조건으로 확인하며 기존 수집 간격을 유지한다. 앱의 원문 저장 설정과 Docker 공통 raw/reference 마운트를 제거했다. 기준자료는 명시적 `reference-import` 작업에만 연결한다. ITS CCTV의 원문 보관 수집 진입점도 제거했다.

## 스키마와 초기 반영

최신 모델·DB는0012 기준이다. 원문 모델·저장소·재생 모듈은 제거했다. 새 DB는 마이그레이션 후 선행 경계와 현재 기준파일을 명시적으로 반영한 뒤 정기 관측을 수집한다. 과거0009 이관 과정의 중간 파일은 최신까지 적용한 뒤 임시 디렉터리와 함께 삭제한다.
