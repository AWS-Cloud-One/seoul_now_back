# 회차 처리 작성 위치

수집·정규화·검증·DB 적재를 한 작업으로 연결한다.

- `citydata.py`: 장소별 도시데이터 수집과 전체 회차. 전체 회차는 주차 반영 결과까지 포함해 상태를 반환한다.
- `parking.py`: 주차 등록정보 수집, 시영주차 좌표 연결·적재, 저장된 도시데이터의 주차 반영. 재처리는 원본 연결·수신 시각을 유지하고 전체 주차 목록 교체로 취급하지 않는다.
- `snapshots.py`: 공통 스냅샷 처리. 원본 보관, 제공처별 정규화 호출, 성공·부분 처리·실패 판정과 저장소 호출을 연결한다. `save_snapshot()`은 `SnapshotResult`를 반환하며, 호출자는 바깥 트랜잭션을 커밋한 뒤 결과를 보고한다. 정상 회차에 대한 중복 성공·부분 처리 attempt는 별도 기록 없이 `None`을 반환한다.
- `supplemental.py`: SGIS·S-DoT·CCTV·전국 주차의 선행 경계 확인, 수집, 공간 처리, 저장·결과 집계를 연결한다. 공간 SQL은 `SpatialRepository`에 둔다. S-DoT·CCTV는 서울 경계를 확인한 후 요청하며, 외부 요청 전에 조회 세션과 잠금 연결의 트랜잭션을 닫는다. 출처별 세션 잠금은 처리 종료까지 유지한다.
- `official_files.py`: TOPIS 도로·공식 ID 매핑과 121장소 경계를 가져온다. 파일은 DB 트랜잭션 전에 읽고, 도로선 구성·좌표 변환·거리 비교·내부 링 보존은 `SpatialRepository`를 호출한다. TOPIS는 공식 매핑으로 연결된 도시데이터 도로와 최대 100개 표본을 비교하며, 10개 이상·상위 중앙값 30m 이하 조건을 통과해야 저장한다. 검증 실패는 쓰기 전에 실패 결과로 반환하고, 저장 결과는 커밋 후 반환한다.
- `topis.py`: 공식 도로 ID·최근 시도 조회를 대상 선정에 연결하고, 중복을 제거한 링크를 동시 최대 8개·요청 시작 간격 최소 0.05초로 수집한다. 선택 조회를 닫은 뒤 요청하고 각 응답 저장을 커밋한 후 결과를 보고한다. 시작·50개 처리마다·종료 시 기존 진행 보고서를 저장한다. 한도·인증 오류는 새 요청을 중단하고 이미 시작한 요청은 마무리한다. 예상하지 못한 작업 오류는 나머지 작업을 취소·정리한 뒤 전파한다.

`topis_rules.py`는 공식 서비스 도로 ID 목록에서 전체 또는 자동 순환 대상을 고르는 순수 규칙을 담는다. 자동 순환은 미시도 링크부터 최근 시도가 오래된 순서로 선택한다. 성공·부분 처리·실패 회차를 모두 시도로 취급하며, 관측 없음은 회차 결과에서 부분 처리로 분류한다. DB 조회와 실제 요청은 `topis.py`에서 수행한다.

필드 변환은 `normalizers/storage_fields.py`, 출처·대상 식별과 처리 버전·지문은 상위 모듈의 `identity.py`, SQL·참조 검사는 `NormalizedWriter`, 회차 종료 기록은 `CollectionRepository.finish()`가 맡는다. 원본 보관 전 인증정보 제거는 `app/storage/redaction.py`에 둔다. 구형 조회 호환 코드는 제거했으며 저장 결과는 통합 테스트에서 검증한다. 저장소에서 파이프라인을 역으로 가져오지 않는다.

수집 내부의 기준정보 조회는 `ReferenceRepository`를 사용한다. TOPIS 대상은 `road_links`, 순환 시각은 `collection_runs`, S-DoT·CCTV의 서울 경계는 `region_boundaries`에서 읽는다. 원문 파일을 열지 않으며 마지막 정상 적재 기록과 `last_payload_id`가 일치하는 활성 자료만 사용해 이전 적재본의 잔여 행이 섞이지 않도록 한다. 기준정보에는 관측값의 짧은 유효시간을 적용하지 않고, S-DoT에 기록하는 경계 연도는 저장된 `source_version`을 사용한다.

TOPIS의 과거 장소 지정 수집 옵션은 제거했다. 수집 대상 선정에는 장소·도로 관계 테이블을 추가하지 않는다. 공식 매핑 데이터와 공식 좌표 교차 검증·주차 재처리의 원문 입력은 유지한다. 도시데이터 자체의 장소별 수집과 API 지역 조회 필터는 별개 기능으로 유지한다.

- `jobs/`에서 받은 엔진·HTTP 클라이언트·수집 함수 등 실행 자원을 사용하며 `app.api.dependencies`나 FastAPI 앱, 다른 실행 파일을 가져오지 않는다.
- 공통 Repository를 사용하고, 한 번에 반영해야 할 쓰기의 트랜잭션 경계는 여기서 관리한다. 네트워크 수집 중 장시간 DB 트랜잭션을 유지하지 않도록 설계한다.
- 회차 식별·중복 실행·부분 실패·마지막 정상 자료·늦은 쓰기 처리 계약을 데이터·백엔드·AWS 담당과 맞춘다.
- 성공 여부와 종료 상태를 `jobs/`로 전달한다. 수집 실패를 성공한 빈 목록이나 종료 코드 0으로 숨기지 않는다.
