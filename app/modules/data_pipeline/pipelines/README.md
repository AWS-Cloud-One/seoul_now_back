# 회차 처리 작성 위치

수집·정규화·검증·DB 적재를 한 작업으로 연결한다.

스케줄러는 해당 수집의 시작 전과 비정상 종료 후 별도 세션에서 공개를 복구한다. 강제 종료된 수집기의 `finally`에 의존하지 않으며, 부모까지 종료되면 다음 실행의 수집 전 복구가 적용된다. 재시도·시간 제한과 실패 후 대기는 [작업 실행 안내](../../../../jobs/README.md)를 따른다.

- `publication.py`: 저장 커밋 후 기존 지도 공개 서비스를 별도 트랜잭션으로 호출하고 `publication` 결과를 반환한다. 정적 기준본 변경은 지물·관측을 함께 교체하고 동적 수집은 보통 관측만 갱신한다. 공개 기준본이 없거나 정형 기준본과 다르면 검증된 정형 자료로 기준본·관측을 함께 복구한다. 실패 시 이전 공개본을 유지하며 정형 기준본 자체가 없으면 보류한다. 수동 `jobs.publish_map`도 유지한다.
- `citydata.py`: 장소별 도시데이터 수집과 전체 회차. 전체 회차는 주차 반영 결과까지 포함해 상태를 반환한다. 공통 인증·한도 오류는 남은 장소 요청을 중단하고 완료/남은 대상 수를 반환한다.
- `parking.py`: 주차 등록정보 수집, 시영주차 좌표 연결·적재, 저장된 도시데이터의 주차 반영. 페이지 일부 실패 시 성공한 행만 저장하고 `partial`·오류·불완전 목록을 기록해 누락 시설을 비활성화하지 않는다. 인증·한도 중단도 성공분 저장·공개 후 중단 상태를 반환한다. 재처리는 원본 연결·수신 시각을 유지하고 전체 주차 목록 교체로 취급하지 않는다.
- `snapshots.py`: 공통 스냅샷 처리. 원본 보관, 제공처별 정규화 호출, 성공·부분 처리·실패 판정과 저장소 호출을 연결한다. `save_snapshot()`은 `SnapshotResult`를 반환하며, 호출자는 바깥 트랜잭션을 커밋한 뒤 결과를 보고한다. 정상 회차에 대한 중복 성공·부분 처리 attempt는 별도 기록 없이 `None`을 반환한다.
- `supplemental.py`: SGIS·S-DoT·CCTV·전국 주차의 선행 경계 확인, 수집, 공간 처리, 저장·결과 집계를 연결한다. 공간 SQL은 `SpatialRepository`에 둔다. S-DoT·CCTV는 서울 경계를 확인한 후 요청하며, 외부 요청 전에 조회 세션과 잠금 연결의 트랜잭션을 닫는다. 출처별 세션 잠금은 처리 종료까지 유지한다.
- `official_files.py`: TOPIS 도로·공식 ID 매핑과121장소 경계를 가져온다. 파일은 DB 트랜잭션 전에 읽고 공간 처리는 `SpatialRepository`를 호출한다. 공식 매핑에 따른 CITYDATA 도로의 대응 구간 길이·포함 범위·선형 이탈을 검사한다. 전체 일치90% 이상·독립 서비스ID/표준ID/형상 각각10개 이상을 만족하면 부분 겹침은 경고로 남기며 분리·교차·형상 불일치 등은 해당 서비스 링크만 격리한다. 격리된 도형과 관계는 가공본 보고서에 보존하고 활성 도로·현행 매핑·수집·공개에서 제외한다. 광범위 불일치·충돌/무효 좌표·자료 부족은 전체 교체를 보류한다. 결과는 커밋 후 반환한다.
- `topis.py`: 도로 대상 선정·동시 수집·도로별 제한 재시도와 회차 결과를 관리한다. `topis_storage.py`는50건/1초 임시 저장·종료 시 통합·중단 복구를 맡고 `repositories/topis.py`는 최신 시도 상태와 최근20회 보관을 관리한다.

`topis_rules.py`는 공식 서비스 도로 ID 목록에서 전체 또는 자동 순환 대상을 고르는 순수 규칙을 담는다. 자동 순환은 미시도 링크부터 최근 시도가 오래된 순서로 선택한다. 성공·부분 처리·실패 회차를 모두 시도로 취급하며, 관측 없음은 회차 결과에서 부분 처리로 분류한다. DB 조회와 실제 요청은 `topis.py`에서 수행한다.

TOPIS의 네트워크/타임아웃·HTTP5xx 실패는 해당 도로만0.5초·1초 뒤 최대2회 추가 호출한다. 재시도도 전체 요청 간격·동시 작업 수 제한을 공유하고 쓰기 트랜잭션 밖에서 수행한다. 최종 도로별 결과를 한 번 저장하며 회차 보고서의 `retry_attempts`로 추가 호출을 별도 집계한다. 성공/부분 처리된 도로와 실패 도로가 섞이면 `partial`로 반환해 전체10분 주기를 유지한다. 처리된 도로 없이 일반 오류로 실패한 회차는 `failed`, 인증/한도 중단은 `paused_provider_limit`을 유지한다.

필드 변환은 `normalizers/storage_fields.py`, 출처·대상 식별과 처리 버전·지문은 상위 모듈의 `identity.py`, SQL·참조 검사는 `NormalizedWriter`, 회차 종료 기록은 `CollectionRepository.finish()`가 맡는다. 원본 보관 전 인증정보 제거는 `app/storage/redaction.py`에 둔다. 구형 조회 호환 코드는 제거했으며 저장 결과는 통합 테스트에서 검증한다. 저장소에서 파이프라인을 역으로 가져오지 않는다.

수집 내부의 기준정보 조회는 `ReferenceRepository`를 사용한다. TOPIS 대상은 `road_links`, 순환 시각은 `collection_runs`, S-DoT·CCTV의 서울 경계는 `region_boundaries`에서 읽는다. 원문 파일을 열지 않으며 마지막 정상 적재 기록과 `last_payload_id`가 일치하는 활성 자료만 사용해 이전 적재본의 잔여 행이 섞이지 않도록 한다. 기준정보에는 관측값의 짧은 유효시간을 적용하지 않고, S-DoT에 기록하는 경계 연도는 저장된 `source_version`을 사용한다.

TOPIS의 과거 장소 지정 수집 옵션은 제거했다. 수집 대상 선정에는 장소·도로 관계 테이블을 추가하지 않는다. 공식 매핑 데이터와 공식 좌표 교차 검증·주차 재처리의 원문 입력은 유지한다. 도시데이터 자체의 장소별 수집과 API 지역 조회 필터는 별개 기능으로 유지한다.

도로 기준본은 `normalizers/road_reference.py`의 품질/전환 조건을 통과해야 `repositories/road_reference.py`가 활성 도로·현행 매핑·행정동 교차를 원자적으로 교체한다. 공간 검증 통과 근거가 없는 가공본도 저장 단계에서 거절한다. 전체 기준본이 아닌 입력은 쓰지 않고, 순번 누락 도로는 실제 제외 목록과 명시한 목록이 정확히 같을 때만 제외한다. 과거 도로는 비활성화하고 소통 관측 FK를 유지한다. 동시 가져오기와 도로 공개는 공통 트랜잭션 잠금을 사용하며 뒤늦은 이전 가져오기는 보류한다. 같은 입력 재적재 시 현행 관계·공간 버전이 중복되거나 달라지지 않는다.

한 가져오기는 원본 XLSX 2개(`source_file`), 가공본(`derived_snapshot`), 처리 보고서(`processing_report`)를 연결한다. 원본의 수신 시각은 미확인이므로 NULL이다. 버전/날짜는 파일별로 기록하고 가공본의 `reference.inputs`가 각 원본 payload를 참조한다. `unit=link`, `scope=road_reference_import`는 링크 채택 수이고, 매핑 행·순번 경고는 별도 품질 수량이다. 전체 파일에서 검토한 제외가 있으면 `completeness=complete`와 `status=partial`이 함께 가능하다. `processing.updated`로 실제 전환 여부를 확인한다.

TOPIS는 응답 직후 수신 시각을 확보하고, 요청 링크와 정확히 일치하는 단일 행만 정규화한다. 두 수치가 유효하면 성공, 하나만 유효하면 새 응답의 유효값과 NULL을 함께 저장하고 부분 처리한다. 이전 수치를 채워 서로 다른 시점의 관측을 합치지 않는다. 전부 결측/무효면 실패 회차를 기록하고 기존 값·시각·원문 참조를 유지한다. 수신 시각이 없거나 역행하는 쓰기도 보류한다. 저장소는 같은 링크의 동시 갱신을 트랜잭션 잠금과 조건부 upsert로 보호한다.

자동·수동 TOPIS 수집은 도로별 `processing`·응답·실제 수신 시각을 `topis:cycle` 파일의 `entries`로 통합한다. `collection_runs`는 회차당1행이며 최신20회만 유지한다. 도로별 최근 시도는 `road_traffic_attempt_latest`에서 갱신한다. `road_traffic_latest.received_at`은 각 응답의 수신 시각이며 통합 파일 생성 시각으로 대체하지 않는다. 기존 입력 재생용 `save_snapshot(topis:link)`는 유지하지만 실제 수집기는 그 경로로 도로별 이력을 생성하지 않는다. 부분값을 저장한 응답은 accepted=1이고 필드 품질은 개별 `processing`에 남긴다. 기존 값·공개본이 참조하는 오래된 원문은 로그가 삭제돼도 유지한다.

- `jobs/`에서 받은 엔진·HTTP 클라이언트·수집 함수 등 실행 자원을 사용하며 `app.api.dependencies`나 FastAPI 앱, 다른 실행 파일을 가져오지 않는다.
- 공통 Repository를 사용하고, 한 번에 반영해야 할 쓰기의 트랜잭션 경계는 여기서 관리한다. 네트워크 수집 중 장시간 DB 트랜잭션을 유지하지 않도록 설계한다.
- 회차 식별·중복 실행·부분 실패·마지막 정상 자료·늦은 쓰기 처리 계약을 데이터·백엔드·AWS 담당과 맞춘다.
- 성공 여부와 종료 상태를 `jobs/`로 전달한다. 수집 실패를 성공한 빈 목록이나 종료 코드 0으로 숨기지 않는다.

- `national_parking.py`: 전국 주차 각 기능/페이지 원문을 먼저 보관하고 시설 등록 → 관리 ID별 운영·현황 연결을 원자적으로 처리한다. 실패/미수집 기능은 기존 정형값을 지우지 않는다. 기능별 처리 결과는 `processing_report`, 집계는 `collection_runs`에 기록한다. 전국 자료를 범용 `save_snapshot()`으로 보내면 전용 페이지 근거 경로가 필요하다는 사유를 반환한다.

시설·운영의 페이지 진행 상태도 기존 처리 보고서에 포함해 같은 저장 트랜잭션에서 확정한다. `repositories/national_parking_progress.py`가 마지막 커밋된 상태를 읽으며 HTTP 실패 페이지·DB 저장 실패·오래된 배치 재생으로 진행 위치를 건너뛰거나 역행하지 않는다. 예전 입력 재생에 페이지 정보가 없으면 현재 진행 상태를 유지한다.

SGIS `prepare_areas()`는 행별 savepoint에서 도형을 검사하고 제한적으로 복구한다. 복구 전후 도형 유효성·면적과 거절 사유를 `geometry_quality`에 남기며 파싱 실패가 다른 행을 롤백하지 않는다. 원래 행/경계 응답은 가공본의 `source_input`에 보존한다. 정형 저장에서 거절한 행은 기존 정상값을 유지하고 채택/거절 수로 success/partial/failed를 구분한다.

CITYDATA 주차 보완 병합은 가공본에 필드별 원문 행 참조를 기록한다. 등록 기준 payload와 현황의 원래 관측 payload·수신 시각을 따로 전달하므로 등록 갱신·반복 투영이 빈자리 관측의 시각을 새로 만들지 않는다.

도시데이터 수집의 `citydata_storage.py`는 전체 응답 → 선택 가공본 → 섹션 처리 보고서를 연결한다. 인구 SQL 실패는 savepoint로 격리해 주차·도로 입력을 유지한다. 인구의 실제 쓰기/보존 관측은 `sections.population`, 주차의 실제 쓰기는 별도 투영 보고서에 기록한다. 인구 부분값 저장은 해당 섹션의 accepted=1이어도 processing=partial일 수 있다. 원문 부모가 있는 선택본을 우선 읽고, 기존 provider_response/legacy_snapshot만 있는 자료도 같은 선택 계약으로 변환한다. 처리 보고서를 주차/도로 입력으로 사용하지 않는다.

`sdot.py`의 `save_sdot()`은 원본 XLSX·성공 페이지 전체 JSON 보관 → 입력 전처리 → 원문 행/수신 시각 대응 확인 → 서울 폴리곤 필터 → 가공본 보관 → 기준정보·관측 상태 원자적 저장 → 처리 보고서 순서다. 원문 페이지의 실제 수신 시각을 보존하고, XLSX·가공본·보고서의 수신 시각은 NULL이다. 가공본의 `input_rows`는 원문 페이지 payload/행, `reference`는 설치 파일, `boundary`는 실제 사용한 경계 버전/payload를 참조한다. 범용 `save_snapshot()`은 페이지 근거 없는 센서 적재를 거절한다.

`repositories/sensors.py`는 `pedestrian_sensors`의 설치 정보와 `pedestrian_sensor_latest`의 마지막 유효 관측/최근 시도를 저장한다. 조회에 없는 센서는 미관측으로 남긴다. 삭제·비활성화는 검토된 전체 설치 기준본이고 거절 행이 없을 때만 가능하다. 빈/부분/충돌 파일은 누락 센서를 비활성화하지 않는다. 관측·수신·회차 시각 역행과 같은 측정의 DATE 역행을 보류한다. 같은 측정 시각의 더 늦은 DATE는 갱신하며, 두 시각이 모두 같은 수치 충돌은 보류한다. DATA_NO 변경 자체는 갱신 차단 사유가 아니다. 같은 관측을 재처리해도 원래 수신 시각·payload를 바꾸지 않는다. 저장 실패 시 두 정형 테이블을 함께 롤백하고 원문·실패 보고서는 보존한다.

`unit=sensor`, `scope=sdot_reference_and_attempt_storage`의 accepted는 기준정보·시도를 기록한 센서 수다. 실제 유효 관측 쓰기는 `storage.observations_written`, 기존 값 보유/기준본 일치는 `storage.sensor_results`에 별도로 표시한다. `observation_quality`는 공간 필터 전 행 품질이며 `observation_summary`는 필터 후 이번 입력의 상태다. 소비 시 active 여부·관측의 reference_version과 설치 source_version 일치·관측/수신 시각·최근 시도 상태를 함께 확인해야 한다. 센서 모델도 정식 0010에 포함되며 기존 DB는 전환 후 사용한다.

`CityDataRepository.list_latest(section=...)`는 섹션별 최신 사용 가능한 입력과 마지막 시도를 함께 반환한다. 누락/무효 섹션은 이전 입력을 재사용하되 원래 payload·수신 시각을 유지하고 `reused_previous`로 표시한다. 정상 빈 목록은 이전 자료로 대신하지 않는다. 주차 투영은 사용한 입력 목록·현재 회차 여부·실제 채택/거절/중복/충돌을 processing_report에 남긴다. 도로 가져오기도 사용한 섹션 근거를 보고하며, 최신 도로 섹션의 무효를 과거 정상 좌표로 숨겨 교체하지 않는다. 시영주차의 좌표 보완본은 원문을 부모로 가진 derived_snapshot으로 저장한다.

위치 저장은 동일 좌표·도형이면 공간 컬럼을 UPDATE에서 제외한다. 수신·처리 근거와 관측값 갱신은 유지하며 주차·도로·인구 경계·행정 경계·S-DoT에 적용한다. 지도 공개도 변경된 지물만 쓴다. 정형 저장과 공개는 각각 기존 트랜잭션을 유지하고, API는 별도의 읽기 전용 REPEATABLE READ 세션으로 한 요청의 스냅샷을 고정한다. 상세 범위와 동시성 검증은 [후속 기록](../../../../tests/integration/test_spatial_write_changes.py)을 따른다.
