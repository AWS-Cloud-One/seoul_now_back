# DB 자동 갱신 실행 결과

2026-11-03, `codex/db-refresh-integration` 작업본에서 Docker 복구 후 검증했다.

## 기존 DB 보존과 마이그레이션

기존 컨테이너는 바탕화면의 소스를 사용하고 있었고 DB revision은 `0007`이었다.
기존 `0006` 인구 테이블과 `0007` 이력을 작업본에 가져왔다. 신규 수집 이력과 조회 인덱스는
`0008`로 추가했다. 기존 revision을 강제로 stamp하거나 기존 테이블을 삭제하지 않았다.

적용 전 백업은 `data/raw/db-backups/seoul-before-refresh-20261103.dump`에 저장했다.
백업 크기는 3,407,656바이트이며 Git과 Docker 이미지에서 제외된다.

개발 DB에 `0007 -> 0008` 적용을 완료했다. `alembic current`는 `0008 (head)`,
`alembic check`는 `No new upgrade operations detected.`를 반환했다.
기존 인구 테이블 두 개도 보존된다. 적용 전 두 테이블의 데이터는 각각 0건이었다.

## 실제 수집과 조회

도시데이터 첫 회차는 00:56경 시작해 00:57경 완료했다. 공식 장소 121곳이 모두 성공했다.
도시데이터 주차 투영도 1,593건을 정상 적재했다. 최신 도시데이터는 121행을 유지했고,
전체 주차 기록은 기존 3,103행에서 3,104행으로 바뀌었다. 이력은 응답 122건과 관측 1,714건이다.

두 번째 회차는 01:01:25에 자동 시작해 01:02:23에 121곳 모두 성공으로 완료했다.
첫 회차 시작과의 간격은 약 300초다. 두 회차 완료 후 최신 장소는 121행을 유지했고,
응답 이력은 244건, 관측 이력은 3,428건으로 증가했다. API readiness와 프론트 조회도 정상이다.

API readiness는 `ok`, 프론트엔드 페이지는 HTTP 200을 반환했다.
프론트엔드의 `/api/v1/map/population` 프록시로 121개 장소를 읽었다.
최근 수집 결과 API에서도 성공 상태와 수집 시작·완료 시각을 확인했다.

## 실행 환경

격리 PostGIS DB에서 전체 테스트 75개가 통과했다. 새 DB 마이그레이션, 모델 일치,
최신값 upsert, 실패 시 롤백, API 조회와 scheduler DB 잠금의 중복 방지·해제를 확인했다.
Ruff와 `git diff --check`도 통과했다. Starlette 테스트 클라이언트의 의존성 사용 중단 경고가
1개 남아 있으며 테스트 실패는 없다.

백엔드: `http://localhost:8000`, 프론트엔드: `http://localhost:5173`.
Docker 컨테이너는 현재 작업 폴더의 코드를 사용한다. 바탕화면 소스는 수정하지 않았다.
DB·API·수집 worker에 `unless-stopped`를 설정했다. Docker Desktop이 실행 중이어야 수집한다.
도시데이터 작업은 회차 시작 기준 300초 간격이다. 설정된 키가 없는 주차 작업은 건너뛴다.
호스트 DB 주소와 컨테이너 DB 주소를 분리해 `.env`의 localhost가 컨테이너 연결을 막지 않게 했다.

전체 도시데이터 수집 중 일부 장소가 실패하면 자식 작업이 종료 코드 1을 반환하도록 고쳤다.
worker는 실패를 기록하고 다음 주기에 재시도한다. 동시 실행은 DB advisory lock으로 막는다.

AWS 배포와 Bedrock 비교는 수행하지 않았다.

## 추가 API 스케줄 확장

01:08경 기존 바탕화면 프로젝트의 키 설정 중 작업 폴더에서 빠진 항목을 가져와
8종 기본 작업을 시작했다. S-DoT 126개 센서, ITS CCTV 48개, SGIS 행정동 426개 저장을 확인했다.
서울 주차 기본정보는 2,178행 중 좌표가 유효한 1,453행, 시영 실시간 주차는 122행 중
53행이 지도용 테이블에 반영됐다. 좌표 없는 원본 기록은 별도 보존한다.
TOPIS 첫 배치는 200개 중 194개 성공, 6개 관측 없음이었다.
교통안전공단 주차는 현황·운영정보 각각 5,000행(상한으로 일부 수집), 실시간 237행을
저장했다. 기능별 자료의 행 수는 서로 다른 기록이므로 합계를 주차장 개수로 해석하지 않는다.
확장 후 전체 테스트 79개가 통과했다. 부분 적재와 관측 없음은 worker의 `partial`로 표시한다.
서울시 도시데이터와 별도로 주차·도로·센서·카메라·행정동 스케줄이 실행된다.

## 이어서 실행한 최종 확인

2026-11-03 재개 시 Docker 29.1.3이 정상 응답하고 DB·API가 healthy인 것을 확인했다.
개발 DB는 `0008 (head)`이며 `alembic check`도 변경 없음으로 통과했다.
조회 시점의 최신 장소는 121행, 주차 기록은 3,104행, 응답 이력은 1,018행이었다.
이력은 자동 수집 중 계속 증가하므로 위 수치는 확인 시점의 값이다.
API readiness `ok`와 프론트 프록시를 통한 121개 장소 조회를 다시 확인했다.

한국교통안전공단 주차 데이터의 `complete: false`가 있는 부분 수집도 `success`로
기록되던 부분을 보완했다. 이제 DB 회차와 마지막 시도는 `partial`, CLI 종료 코드는 2이며,
스케줄러도 부분 수집으로 표시한다. 로그의 records는 기능별 실제 수신 행 수의 합이다.
새 코드로 worker를 재시작했고 기존 최신값을 보존했다.
재시작 후 주차 보조 데이터 10,237행이 `partial`·종료 코드 2로 기록되는 것을 확인했다.
같은 실행에서 도시데이터 121곳과 주차 투영도 다시 성공으로 완료됐다.

보완 후 격리 PostGIS DB에서 **82개 테스트 모두 통과**, 건너뛴 테스트는 없다.
Ruff와 `git diff --check`도 통과했다. 기존 Starlette 경고 1개는 그대로다.
변경 파일은 작업 브랜치에 저장돼 있으며 커밋·push와 AWS 배포는 수행하지 않았다.
