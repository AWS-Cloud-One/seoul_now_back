# 단발 수집 실행 진입점

> 최신 스키마는0012입니다. 원문 파일 없이 정형 DB에 직접 적재하며 API·정기 수집은 DB의 기준정보만 사용합니다.


## 저장 후 지도 공개

수집·정형 저장을 먼저 커밋하고 지도 공개는 별도 트랜잭션으로 처리한다. 최상위 `status`는 기존 수집/처리 결과이며, `publication.status`와 `publication.layers`가 공개 성공·실패·보류를 나타낸다. 저장 성공 후 공개 실패/보류라면 종료 코드 `2`를 반환한다. 기존 수집 실패 `1`·부분 처리 `2`·제공처 중단 `4`는 유지한다.

| 실행 | 공개 처리 |
| --- | --- |
| 서울/시영/전국 주차 수집, 도시데이터 주차 저장 | 주차 위치·이름·식별 상태가 달라질 때만 공개 지물 교체 |
| TOPIS 도로 기준 파일 가져오기 | 검증된 기준본 커밋 후 도로 지물·관측 공개 |
| 공식 장소 경계 가져오기 | 인구 관측 영역·관측 공개 |
| TOPIS 수집 | 회차 종료 후 도로 관측만 갱신 |
| 도시데이터 단일 수집 | 같은 응답의 인구·주차를 저장한 뒤 각각 공개 |
| 도시데이터 전체 수집 | 현재 회차의 주차 후보 병합·저장 후 주차·인구 공개 |

관측 갱신은 기존 도로선/경계와 `geometry_version`을 유지한다. 공개된 기준본이 없거나 검증된 정형 기준본과 다르면 기준본과 관측을 같은 트랜잭션으로 복구한다. 정형 기준본 자체가 없을 때만 보류하며, 공개 SQL 실패는 이전 공개본을 유지한다. `python -m jobs.publish_map roads`처럼 해당 레이어(`roads`, `population`, `parking`)를 명시한 수동 재시도도 가능하다. 같은 자료를 재공개하면 중복 지물을 만들거나 공개 시각을 새로 쓰지 않는다.

스케줄러는 주차·TOPIS·CITYDATA의 수집 시작 전에 이전에 커밋된 자료의 공개를 확인한다. 수집 자식 프로세스가 시간 초과·취소·오류로 끝나거나 비정상 종료 코드를 반환하면 종료를 확인한 뒤 같은 작업 잠금을 유지하며 공개를 복구한다. 공개 오류는1초 후 한 번 더 시도하고 각 시도는120초로 제한한다. 부모 스케줄러까지 종료된 경우 다음 실행의 수집 전 복구를 사용한다. 이 과정은 외부 API를 다시 호출하지 않으며 수집 결과와 공개 결과는 따로 보고한다. 기존 수집 주기·실패 대기는 유지한다.

공개 실패는 이미 커밋한 수집 결과를 되돌리지 않으며 이전 공개본을 유지한다. 저장 후 프로세스가 종료된 경우도 같은 공개 명령으로 복구한다. 자동 재시도 큐나 스케줄 주기는 추가하지 않았다. S-DoT는 기존 정형 센서 저장까지만 처리하며 새 지도/API 레이어를 만들지 않는다.

## 수집 실행

데이터 처리 담당이 작성하고 AWS 담당이 실행 명령·종료 상태를 연결한다. API와 같은 코드·설정·DB 모델을 사용하되 별도 프로세스로 실행한다.

- `python -m jobs.collect_parking`: 서울 공영주차장 등록 기본정보 수집. `.env`의 `APP_SEOUL_API_KEY` 사용.
- `python -m jobs.collect_citydata --area "광화문·덕수궁"`: 현재 응답의 인구·주차 필드만 검증해 DB에 저장. `.env`의 `APP_SEOUL_CITYDATA_API_KEY` 사용.

Citydata는 요청1회에 장소1곳을 조회한다. 개별 장소는 `collect_citydata`, 전체 수집은 `collect_citydata_all`을 사용한다. DB에 반영된 활성 장소 목록에서 이름·코드를 조회해 응답과 대조한다. 전체 회차는 여러 장소의 주차 후보를 메모리에서 모아 중복·충돌을 판단하고 정형 저장한다. 응답 원문·선택본·처리 보고서는 파일로 보관하지 않으며, 저장 원문을 읽는 주차 재처리 명령은 제거했다.

`collect_citydata --area`에는 공식 장소명 또는 코드(예: `POI009`)를 넣는다. 결과 코드·장소 불일치는 실패 사유만 기록한다. `unit=section`, `scope=citydata_section_processing`은 인구 처리와 주차 입력 준비의 두 항목 집계다. `sections.population`에서 필드 품질·실제 쓰기·유지한 관측을 확인하고, `parking_storage`에서 실제 주차 적재·중복·충돌을 확인한다. 인구 SQL 실패는 주차 후보를 폐기하지 않는다. 주차 누락·무효·빈 목록에는 기존 DB 값을 유지하며 과거 응답을 재처리하지 않는다. 도로 좌표는 별도 기준정보 반영 시 현재 응답에서만 추출한다.

진입점 담당 순서:

1. 실행 인자와 `app/core/config.py` 설정을 읽는다.
2. `app/db/session.py`의 `create_engine()`으로 작업 전용 DB 연결을 만든다.
3. HTTP 클라이언트를 열고 `app/modules/data_pipeline/pipelines/`의 회차 처리를 호출한다.
4. 민감정보를 제외한 결과를 JSON 한 줄로 출력한다.
5. 클라이언트와 엔진을 닫고 성공/실패 종료 코드를 반환한다.

저장 작업은 수집 원문뿐 아니라 정규화 결과까지 확인한다. 정규화 실패 시 기존 정상값을 유지하고 실패 기록을 남기며, 부분 처리도 성공으로 보고하지 않는다. 단발 명령의 종료 코드는 성공 `0`, 실패 `1`, 부분 처리 `2`다. 잠금으로 건너뛴 수집은 `3`, 인증·한도 문제로 중단한 TOPIS/CITYDATA 회차는 `4`를 사용한다.

모든 실행 모듈은 동기 `main()`에서 CLI 인자를 처리하고 비동기 `execute()`에서 자원 준비·결과 출력 후 정수 종료 코드를 반환한다. `jobs/runtime.py`가 JSON 한 줄 출력, 상태별 종료 코드, 실행 예외와 사용자 중단(`130`)을 공통 처리한다. 파이프라인은 처리 결과를 반환하며 직접 프로세스를 종료하지 않는다. 스케줄러는 개별 작업 코드와 실행 조건을 종합해 단발 실행의 성공 여부를 반환한다.

공식 자료 경로 `REFERENCE_DATA`(`data/`)는 명시적 기준정보 반영 명령에서만 사용한다. API·정기 수집은 DB의 기준정보를 사용하며 raw 경로·원문 저장 환경변수·공통 파일 마운트가 없다. 공식 XLSX·ZIP은 Git으로 공유하고 기준정보 반영 컨테이너에만 읽기 전용으로 연결한다.

각 분야는 전용 파이프라인으로 정형 저장한다. 원문만 보관하던 ITS CCTV 수집 진입점과 `--reuse-probe`는 제거했다. 구형 원문 저장 모듈·모델과 해당 보관 동작을 검증하던 테스트도 제거했다.

`python -m jobs.collect_supplemental areas|sdot|parking`은 SGIS·S-DoT·전국 주차 수집을 연결한다. 요청은 collector, 값 변환은 normalizer, 공간 조회는 repository가 맡는다. S-DoT는 DB의 서울 경계와 해당 버전의 센서 설치정보가 있어야 호출한다. HTTP 대기 중 DB 쓰기 트랜잭션을 열어두지 않는다.

SGIS는 `https://sgisapi.mods.go.kr/OpenAPI3/`를 사용한다. 행정동·서울 경계를 행별로 검사하고, 무효 Polygon/MultiPolygon은 유효한 면 도형으로 복구되고 상대 면적 변화가0.1% 이내일 때만 채택한다. 실패한 행의 사유만 기록하며 기존 정상 도형은 유지한다. 다른 정상 행의 저장은 계속한다. 구별 수집 실패에도 성공한 구의 자료는 반영하고 누락 행을 비활성화하지 않는다. 서울·행정동 경계와 그에 따른 도로 관계는 하나의 저장 트랜잭션으로 반영하며 DB 오류면 함께 롤백한다.

전국 주차 시설·운영의 다음 페이지는 `collection_cursors`, 현재 스캔의 중복 확인용 페이지 지문은 `collection_cursor_pages`에 저장한다. 응답 원문이나 처리 보고서를 다시 읽지 않고 DB 상태로 다음 실행을 이어간다. 완료·교체된 스캔의 지문은 삭제하며 수집 로그가 삭제돼도 진행 위치는 유지된다. 현황은 매회1페이지부터 조회하고 기능별 최대5페이지·5,000행 상한을 유지한다. 진행 기록은 정형 저장과 같은 트랜잭션으로 커밋하므로 DB 실패 시 페이지를 건너뛰지 않는다. HTTP 실패 페이지는 다음 회차에서 재시도한다. 제공 총수보다 일찍 끝난 페이지는 다음 회차에도 동일한지 확인한 뒤 불일치 경고와 함께 새 스캔을 시작하며, 전체 수집 완료로 표시하지 않는다.


DB 마이그레이션은 기존 루트 `migrations/`와 Alembic 명령으로 별도 적용한다. AWS 스케줄 연결은 수집 주기와 호출 한도를 합의한 뒤 구성한다.

## 자동 수집

서울시 공식 OA-21285 첨부파일(목록 seq=23)은 data/seoul_areas.xlsx에 보관한다. 명시적인 장소 기준정보 반영 후 jobs.collect_citydata_all은 DB의 활성 장소 목록을 읽어 각각 요청한다. 인증키는 기존 APP_SEOUL_CITYDATA_API_KEY를 사용하며 키를 출력하지 않는다.

도시데이터·주차 명령은 실행 인자·설정·출력만 담당하며 실제 회차 처리는 `app/modules/data_pipeline/pipelines/`에 있다. 공식 장소 목록은 `collectors/citydata.py`에서 읽고, 시영주차 좌표 조회는 `ParkingRepository`, 유일 좌표 연결은 `normalizers/parking.py`에서 처리한다.

전체 수집의 마지막 JSON에서 `success`·`partial`·`failed`·`skipped`는 장소별 수집 건수이고 `parking_projection`은 주차 반영 결과다. 최상위 `status`는 수집·주차 투영 두 단계를 함께 판단한다. 공개 결과는 `publication`으로 분리하며 공개 실패/보류도 종료 코드에 반영한다. 어느 단계든 실패하면 실패, 전부 성공하면 성공, 전부 건너뛰면 건너뜀, 그 밖에는 부분 처리다.

CITYDATA의 공통 인증·한도 오류는 남은 장소 요청을 중단한다. 이때 `status=paused_provider_limit`, `cycle_complete=false`, `stop_reason`, `completed`, `remaining`으로 중단 지점을 알리고 이미 처리한 입력의 주차 투영·공개는 진행한다. 개별 장소의 입력 오류는 다른 장소 처리를 막지 않는다.

실행: `docker compose up -d citydata-collector`
중지: `docker compose stop citydata-collector`
단발 전체 수집: `docker compose run --rm --no-deps api python -m jobs.collect_citydata_all`

서비스 이름은 `citydata-collector`지만 실제로는 `jobs.scheduler`가 아래 작업을 함께 실행한다. 별도 수집 Compose 파일은 사용하지 않는다.

| 작업 | 기본 주기 | 선행 조건 |
| --- | --- | --- |
| 도시데이터 121장소 | 600초(10분) | 서울 도시데이터 키와 DB 활성 장소 기준정보 |
| 주차 등록정보 | 86400초 | 서울시 키 |
| 시영주차장 | 600초(10분) | 시영주차장 키 또는 서울시 키 |
| SGIS 행정동·서울 경계 | 604800초 | SGIS 키·시크릿 |
| S-DoT | 600초 | S-DoT 키, SGIS 서울 경계와 해당 버전의 DB 설치정보 |
| 전국 주차정보 | 3600초(1시간) | 공공데이터포털 키 |
| ITS CCTV 목록 | 비활성화 | 원문 보관만 하던 수집 명령 제거 |
| TOPIS | 600초(10분), 전체 활성 도로 | TOPIS 키 또는 서울시 키와 정형 적재된 공식 도로 자료 |

성공·부분 처리의 주기는 회차 시작 기준이며 작업이 길어지면 완료 후 최소1초 대기한다. TOPIS 전체 수집이10분을 넘기면 완료 후 다음 회차를 시작하며 중복 실행하지 않는다. 실패는 완료 후 별도로 기다린다. SGIS·서울 주차·CITYDATA·시영은300초, S-DoT는600초, 전국 주차·TOPIS는3600초다. 인증·한도 중단 코드4는 최소3600초 대기한다. 키가 없으면 건너뛰고 선행 자료가 없으면 최대60초 뒤 재확인한다. 실제 값은 [scheduler.py](scheduler.py)의 `TASKS`에서 관리한다. 같은 작업의 개별 반복 실행과 스케줄러를 동시에 켜지 않는다.

TOPIS는 성공/부분 처리된 도로가 있으면 다른 도로의 호출 오류가 있어도 회차를 `partial`로 반환해 전체10분 주기를 유지한다. 네트워크·타임아웃·HTTP5xx 오류가 난 도로만0.5초·1초 대기 후 최대2회 추가 시도한다(총3회). 재시도도 동시8개·요청 시작 간격0.05초 제한을 공유하며 DB 저장은 최종 결과에 한 번 수행한다. 관측 없음·잘못된 응답·일반4xx는 즉시 재시도하지 않고, 인증/한도 오류는 신규 요청과 대기 중 재시도를 중단한다. `attempts`는 도로별 실제 호출 횟수, `retry_attempts`는 회차의 추가 호출 횟수이며 완료 도로 수에 중복 집계하지 않는다. 회차 전체 실패나 DB/실행 오류에는 기존1시간 대기를 유지한다.

첫 회차에는 선택·설정된 `areas`가 끝난 뒤 S-DoT, `parking`이 끝난 뒤 시영을 시작한다. 독립 작업은 병렬 실행하며 이후 주기는 각각 유지한다. `--once`는 각 작업의 결과를 마지막 JSON의 `results`에 보존하고 부분 처리는2, 전부 건너뜀은3, 제공처 중단은4로 반환한다. 실패/선행조건 대기는1이다. 복수 스케줄러 간 잠금은 실행 겹침만 막으므로 현재는 작업자1개를 사용한다. 원천 기준 시각과 수집 시각은 구분하며 Docker Desktop이 켜져 있어야 자동 수집이 동작한다.

서울 응답 본문의 `ERROR-500`·`ERROR-600`도 서버 오류로 분류해 같은 제한된 재시도를 적용한다. 서울 주차·CITYDATA 역시 HTTP 200으로 전달된 이 오류를 최대2회 추가 시도한다. 서울 등록·시영주차는 중간 페이지가 실패해도 받은 행을 저장하며, 불완전 목록에서 누락 시설은 비활성화하지 않는다.

선행 경계·도로·장소·센서 설치정보는 `ReferenceRepository.has_prerequisite()`로 정형 테이블에서 확인한다. 파일을 자동으로 읽거나 가져오지 않으며, 선행자료가 없으면 수집을 기다린다. S-DoT 설치정보가 현재 서울 경계 버전과 다르면 운영자의 설치정보 재반영을 기다린다.

위치는 신규 항목 또는 실제 좌표 변경 때만 쓴다. 서울 등록·전국 시설·CITYDATA 주차는 응답에 좌표가 반복되어도 기존 좌표와 같으면 정형 위치 UPDATE에서 제외한다. 시영 현황은 기존 서울 등록정보의 위치를 사용한다. S-DoT 설치점·SGIS 경계·도로선·121장소 경계도 같은 도형의 재쓰기를 생략하고, 수신 근거·현황 등 다른 정보는 각 규칙대로 갱신한다. 공개 지도도 추가·변경·삭제된 지물만 반영한다. TOPIS 소통 수집은 도로선을 갱신하지 않으며 도로선·ID 매핑·121장소 경계의 가져오기는 수동 실행을 유지한다.

API 조회는 요청별 읽기 전용 스냅샷을 사용한다. 갱신 중에는 커밋 전 값을 읽고, 조회 도중 커밋돼도 응답 안에서 이전/새 값이 섞이지 않는다. 정형 저장과 지도 공개는 각각 기존 트랜잭션 단위를 유지하며, 전체 스케줄 회차를 하나의 트랜잭션으로 묶지는 않는다. [구현·동시성 검증](../tests/integration/test_read_snapshot_isolation.py).

## 시영주차장 및 TOPIS

시영주차장 `python -m jobs.collect_municipal_parking`: 현재 응답을 DB의 서울 등록정보와 연결해 좌표가 유일한 행만 정형 적재한다. 원문·좌표 보완본을 파일로 저장하지 않으며 한 실행을 하나의 수집 회차로 기록한다. 개별 명령은 `--interval 600`으로 반복할 수 있으며 Compose 자동 수집은 위 공통 스케줄러를 사용한다.

TOPIS `python -m jobs.collect_topis --link 1220003800` (여러 --link 허용): XML에서 링크 ID·속도·통행시간만 선택해 검증 후 DB에 저장한다. 이 명령은 지정한 링크만 호출한다. TOPIS 서비스 링크별 관측값이며 도시데이터의 표준 링크 ID와 직접 연결하지 않는다.

속도·통행시간 중 하나만 유효하면 부분 처리이며, 둘 다 결측/무효면 실패 사유를 기록하고 마지막 채택값·원래 시각을 유지한다. 정상0은 유효하며 일부 결측을 이전 값으로 채우지 않는다. 실제 수신 시각이 역행한 응답은 `traffic_time_guard`로 보류한다. TOPIS 원천 관측 시각은 미제공이므로 NULL로 유지한다. 원문 XML·선택 응답·회차 보고서는 저장하지 않는다. 도로별 현재 값과 최근 시도는 각각 `road_traffic_latest`, `road_traffic_attempt_latest`에서 확인한다.

`collect_topis`와 `collect_topis_network`는 설정·HTTP/DB 자원·출력·종료 코드를 맡고, 서로를 가져오지 않는다. 공통 수집은 `pipelines/topis.py`, 대상 선정·회차 결과 규칙은 `pipelines/topis_rules.py`, TOPIS 요청은 기존 `collectors/topis.py`에서 처리한다. `collect_topis_network`의 명시적 반복 대기만 실행 파일에 남는다.

자동 수집은 `--all`로 검증된 전체 활성 도로를 선택하며 `--max-links`로 제한하지 않는다. 격리·비활성 도로는 제외한다. 소량 점검용 `--scheduled-batch --max-links N` 옵션은 수동 실행에서 사용할 수 있다. 요청 중 한도·인증 오류가 발생하면 새 요청을 중단하고 종료 코드 `4`를 반환하며, 명시적 반복은 최소1시간 뒤 재개한다. 관측 없음만 발생한 회차는 부분 처리 `2`, 그 외 실패는 `1`이다. 동시 요청 최대8개·요청 시작 최소0.05초 간격과 기존 실패 대기는 유지한다.

회차 마지막 JSON은 기존 `cycle_complete`·`target`·`counts`에 최종 `status`를 함께 출력한다. `cycle_complete`는 선택한 대상 처리가 끝났는지를 뜻하며 전부 성공했다는 의미는 아니다. `completed`·`remaining`·`retry_attempts`·실패 도로 목록을 함께 기록한다. 수집 중에는 같은 회차 행의 진행 수량만 갱신한다.

회차당 `collection_runs`1행과 사유별 집계만 기록하며 최신20회로 제한한다. 진행 중인 회차는 삭제하지 않고, 종료된 최신20회를 유지한다. 초과 로그를 지워도 도로별 관측·최근 시도는 유지된다. 최대50건씩, 또는1초가 지나면 현재 버퍼를 저장하고 정형 관측·최근 시도·회차 수량을 같은 트랜잭션으로 커밋한다. 정상 종료 시 남은 버퍼를 반영한다. 중단 시 이미 커밋한 성공분은 유지하고 미커밋 응답은 폐기해 다음 수집에서 다시 받는다. 다음 수집 전·스케줄러 복구는 DB 집계로 미종료 회차의 상태만 정리하며 파일을 재생하지 않는다. 응답 체크포인트·통합 파일·파일 삭제 대기열은 제거했다. 실행 전에0012 스키마를 적용한다. [보관·중단 검증](../tests/integration/test_topis_retention.py).

TOPIS 전체·자동 순환은 도로 ID·시도 기록을 DB에서 직접 조회한다. 과거 장소 지정 수집 옵션은 제거했으며, 호출할 도로를 고르기 위해 도시데이터 원문이나 표준 ID 매핑을 읽지 않는다. 도시데이터 자체의 장소별 수집, 현재 응답의 실시간 주차 정보와 API 응답 처리는 유지한다.

## 인구·센서 전처리 결과

영역 인구는 범위·등급·대체 여부·시각을 각각 검사하며 `population_quality`에 결과를 반환한다. 수치는 유효해도 메타데이터가 없으면 partial이고 미확인 필드는 NULL로 유지한다. 인구가 없거나 범위/시각이 무효이면 실패 사유만 기록하고 기존 값을 지우지 않는다. `population_latest`의 실제 수신 시각으로 역행을 막고 `population_attempt_latest`에 최근 시도를 분리해 로그 정리 후에도 상태를 유지한다. accepted=1은 해당 응답의 정형 반영을 뜻하고 필드가 모두 완전하다는 의미는 아니다.

S-DoT는 KST 현재 시간대와 직전 2개 시간대만 조회한다. 합계 최대10페이지·1만 행이며 기존 재시도 포함 최대30회 HTTP 시도다. 시간대별 총수·실제 수신 시각·중복·빈 페이지/실패를 기록하고 시간 필터 위반은 채택하지 않는다. 측정 시각·DATE로 직접 최신값을 선택한다. `query_complete`는 선택 시간대의 응답 총수와 받은 행의 일치이며 전 센서 최신값 확보나 요청 간 고정 스냅샷을 뜻하지 않는다.

`records`는 서울 경계 필터 후 설치 위치 수다. `observation_summary.with_count`는 이번 입력에 값이 있는 센서 수, `usable_observations`는 입력의 시각 근거까지 검증된 수이며 TTL 판단은 포함하지 않는다. 원천 행 품질 `observation_quality`는 서울 공간 필터 전의 observation_row 단위다. `accepted`는 설치정보·최근 시도를 기록한 센서 수이고, 실제 유효 관측 갱신 수는 `storage.observations_written`이다. 이번 조회에 없는 센서는 미관측으로 남기고 0명/고장으로 바꾸지 않는다. 설치정보는 별도 반영 명령으로 관리하며 정기 관측은 DB 설치정보와 현재 응답으로 마지막 유효 관측/최근 시도를 저장한다. 원본 XLSX 복사본·페이지 응답·가공본·보고서는 보관하지 않는다. 수신 시각을 모르는 과거 표본은 값이 있어도 시도에만 보존한다. 0012 스키마에서 실행한다.

## 회차 기록과 복구

수집 요약은 작업당1개이며 출처별 종료된 최신20회만 보관한다. 진행 중인 회차는 삭제하지 않는다. CITYDATA 전체/단일 수집과 주차 병합은 하나의 회차 ID를 공유하며 장소별·주차별 별도 로그를 만들지 않는다. `processing` 집계의 단위는 인구 관측1건과 주차 원천 행이다. 주차 중복은 별도로 집계하고, HTTP 실패는 수신0건과 짧은 사유로 남긴다. 실제 반영 수와 집계는 같은 트랜잭션으로 저장한다.

관측값·최근 시도·전국 페이지 진행은 회차 로그 삭제와 독립적이다. 지도는 정형 관측의 실제 수신 시각과 최근 시도 컬럼을 읽는다. 프로세스 중단 시 커밋된 성공분은 유지하고 원문 재생 없이 미종료 회차만 닫는다. 복구는 수집기와 같은 잠금을 얻은 경우에만 실행한다.

## 기준정보 반영

기준파일은 현재 사용할 자료만 `data/`에 둡니다. 파일을 교체하는 것만으로 DB가 바뀌지는 않으며 아래 명시적인 반영 명령이 검증 후 DB를 갱신합니다. 최신 마이그레이션을 적용한 뒤 실행합니다.

| 대상 | 명령 | 반영 기준 |
| --- | --- | --- |
| 장소 목록·경계 | `python -m jobs.import_place_boundaries` | 목록 XLSX와 경계 ZIP의 코드·이름 일치, 공간 검증 후 함께 반영 |
| 도로선·링크 매핑 | `python -m jobs.import_topis_geometry` | 두 XLSX의 버전·좌표·관계를 검증하고 현재 CITYDATA 응답과 메모리에서 대조 |
| 센서 설치정보 | `python -m jobs.import_sensor_locations` | 설치 XLSX의 식별자·좌표를 검증하고 DB의 SGIS 서울 경계와 대조 |

Compose에서는 기준파일을 연결한 전용 작업으로 실행한다.

```bash
docker compose --profile reference run --rm reference-import python -m jobs.import_place_boundaries
docker compose --profile reference run --rm reference-import python -m jobs.import_sensor_locations
# 도로 반영 인자 확인
docker compose --profile reference run --rm reference-import python -m jobs.import_topis_geometry --help
```

`reference-import`를 인자 없이 실행하면 도움말만 출력한다. 정기 worker와 API에는 기준파일을 마운트하지 않는다.

장소는 `--areas-file`, `--boundaries-file`, 센서는 `--file`로 교체 파일을 지정할 수 있습니다. 새 센서 자료의 확인된 기준일은 `--reference-date YYYY-MM-DD`로 전달합니다. 도로는 `--vertices-file`·`--mapping-file`과 각 `--vertices-version`·`--mapping-version`을 사용하며, 날짜가 확인된 경우에만 해당 date 옵션을 넣습니다. 기본 도로 버전은 현재 동봉 파일 해시가 일치할 때만 자동 지정합니다.

동봉 도로선의 정점 순서 누락 링크 `1000020300`은 기존 검토 기준대로 `--allow-excluded-link 1000020300`을 지정해야 합니다. 새 파일의 실제 제외 목록과 옵션이 일치하지 않으면 반영하지 않습니다. 매핑의 미확인 순번·모호함과 공간 검증 기준은 유지합니다.

도로 대조용 응답은 해당 반영 작업에서 필요한 ID·좌표만 추출하고 폐기합니다. CITYDATA 수집 대상은 먼저 DB에 반영한 장소 목록을 사용하며 과거 응답 파일을 읽지 않습니다. 센서 설치 반영은 SGIS 서울 경계가 선행되어야 합니다. 정기 S-DoT 수집은 설치 파일을 읽거나 위치를 갱신하지 않습니다.

정형 저장이 중간에 실패하거나 입력 검증을 통과하지 못하면 같은 반영 단위 전체를 취소하고 이전 기준정보를 유지합니다. 기준파일 복사본·가공본·처리 보고서를 raw에 보관하지 않습니다. DB에는 현재 필요한 값·버전·반영 시각과 짧은 실행 결과를 저장합니다.

파일 경로와 읽기는 jobs/collector, 값 검증은 normalizer, 트랜잭션 조율은 pipeline, 정형 DB 저장은 repository가 담당합니다. 기준정보 반영 이후 정기 수집은 DB의 활성 장소·센서를 조회합니다. 기준정보가 없으면 선행자료 부족으로 종료하며 파일을 자동으로 읽어 채우지 않습니다.

## 공식 입력 자료

`data/`에는 현재 사용할 공식 입력 파일만 유지한다. Git으로 공유하되 실행 이미지에는 포함하지 않으며 명시적 반영 작업과 파일 파서 테스트에만 읽기 전용으로 연결한다. 교체 파일은 검증·DB 반영 명령을 실행해야 현재 서비스 기준에 반영된다.

| 파일 | 내용·출처 | 사용하는 작업 |
| --- | --- | --- |
| `seoul_areas.xlsx` | OA-21285 공식 121장소 목록, 기존 기록의 첨부 seq=23 | `import_place_boundaries` |
| `citydata_places_official.zip` | 기존 저장소의 공식 121장소 경계 SHP 묶음 | `import_place_boundaries` |
| `sdot_locations_20251113.xlsx` | 기존 저장소의 S-DoT 설치 위치 목록, 파일명 기준 2025-11-13 | `import_sensor_locations` |
| `topis_vertices_2025.xlsx` | OA-15060 서비스링크 보간점, 2025 자료 | `import_topis_geometry` |
| `topis_standard_mapping_20250306.xlsx` | OA-15061 표준링크·서비스링크 매핑, 2025-03-06 자료 | `import_topis_geometry` |

- TOPIS 속도·통행시간은 서비스 링크 전체의 관측값이다. 도시데이터의 표준 링크와는 공식 매핑으로 연결하며 비슷한 번호나 인접 위치로 ID를 추정하지 않는다.
- 도로 보간점의 `GRS80TM` 헤더는 기존 EPSG:5181 해석으로 WGS84(4326)에 변환한다. TOPIS 공식 지도 구현의 EPSG:5181 해석을 확인했다. 정점 순서 누락·충돌과 공식 매핑에 따른 CITYDATA 선형을 함께 검증하며 `provider_epsg_confirmed=true`와 공식 코드 근거를 기록한다. 모든 도로 형상·방향 검증 완료를 뜻하지 않는다.
- 짧은 선의 양 끝을 긴 선에 투영한 대응 구간을 비교한다. 포함 비율90% 이상, 대응 구간/짧은 선 길이비0.8~1.25, 10m 이하로 분할한 선의 Hausdorff 거리30m 이하를 내부 기준으로 사용한다. 전체 일치 쌍90% 이상·독립 서비스 ID/표준 ID/형상 각각10개 이상의 근거가 있으면 부분 겹침은 경고로, 분리·교차·형상 불일치 등은 해당 서비스 링크 격리로 처리한다. 격리 도형·관계·판정은 반환 요약에 남기고 활성 도로·현행 매핑·수집·공개에서 제외한다. 광범위 불일치, 좌표 충돌/무효, 검증 자료 부족은 전체 교체를 보류한다.
- 이 수치는 제공처의 정확도 보증이 아니다. 메모리 검증 결과의 미검증 도로 수와 표본 경계 범위를 함께 확인한다. 배열 역순은 기록하지만 통행 방향을 증명하지 않으며, 일부 표본 통과를 전체 서울 도로 검증으로 표시하지 않는다.
- 장소 경계는 121개 고유 장소와 좌표계를 확인하고 내부 링도 보존한다. S-DoT 위치와 최신 관측은 센서 ID로 연결한다.

작은 검증 표본은 `tests/fixtures/`에서 관리한다. 주기적 API 응답·선택본·처리 보고서 파일은 생성하지 않는다.

전국 주차(`collect_supplemental parking`)는 기능별 수집 상태와 정형 처리 결과를 함께 출력한다. 기본·추가 요금 시간은 사용자 확인에 따라 분으로 저장한다. 정상 빈자리 수는 관측 시각 미제공만으로 부분 실패로 처리하지 않으며, 수신 시각 기준 1시간 활용 정책을 따른다. 값 오류·미연결 관리 ID 등 실제 제한은 `partial`로 보고한다. `accepted`는 원천 행의 정형 반영 수이며 현재 사용 가능한 빈자리 수가 아니다. 응답에서 선택한 필요한 필드와 실제 수신 시각으로 정형 저장하며 원문·처리 보고서는 저장하지 않는다. 기능별5천 행 제한을 전체 기준본으로 사용하지 않으며 불완전한 목록에서 누락 시설을 비활성화하지 않는다. 오래된 배치를 다시 전달해도 현재 데이터와 진행 위치를 되돌리지 않는다. 최신 마이그레이션을 적용한 뒤 실행한다.

전국 주차 자동 수집 간격은 1시간이다. 내부 소비자는 `ParkingRepository.availability()`로 최신 활용값을 읽는다. 전국 빈자리는 저장된 최근 수신 수량을 이용하며, `time_basis=received_at`, `observed_at=None`으로 실제 측정 시각과 구분한다. 수신부터 1시간까지 허용하고 그 이후에는 `usable=false`, `available_spaces=None`, `STALE_DATA`다. 범위 충돌·무효 수량·미래 수신 시각은 허용하지 않는다. 제공처가 실제로 1시간마다 갱신한다는 뜻은 아니며 기존 외부 API의 빈자리 제공 기능을 새로 구현한 것은 아니다.

시영·CITYDATA 빈자리는 실제 `observed_at`부터1시간까지 허용하며 미래·미확인·만료 시각은 활용하지 않는다. 최신 응답이 명시적으로 미제공이면 `NOT_PROVIDED`로 수량을 반환하지 않는다. 마지막 유효 관측의 숫자·근거는 DB에 유지하며, DB의 유효 관측 보존 플래그와 현재 조회의 `usable`은 구분한다.

SGIS 행정동 경계 변경·활성 목록 교체와 도로↔행정동 관계 재계산은 같은 트랜잭션에서 처리한다. 수집한 전체 구 목록과 각 구의 동 목록이 비어 있지 않고 모든 요청·도형 검증을 통과한 완전한 기준본만 누락 동을 비활성화한다. 부분·빈·중복 입력은 누락 항목을 삭제하지 않으며 같은 기준본을 반복 적재하면 관계도 다시 쓰지 않는다.

도시데이터 주차는 이번 회차에서 성공적으로 받은 후보만 사용한다. 누락/무효/빈 섹션에서 기존 DB 값을 유지하며 과거 응답은 재처리하지 않는다. `parking_storage`는 실제 반영 수·중복·거절 사유를 반환하며 원문/가공본 ID를 만들지 않는다.
