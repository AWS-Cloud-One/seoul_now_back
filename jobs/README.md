# 단발 수집 실행 진입점

데이터 처리 담당이 작성하고 AWS 담당이 실행 명령·종료 상태를 연결한다. API와 같은 코드·설정·DB 모델을 사용하되 별도 프로세스로 실행한다.

현재는 패키지만 준비되어 있고 **실행 가능한 수집 명령은 없다.** 출처를 정한 뒤 이 폴더에 명시적인 진입 모듈을 추가한다. `python -m jobs.<작업명>`은 그 모듈이 구현된 이후 사용할 명령 형식이다.

진입점이 담당할 순서:

1. 실행 인자와 공통 `app/core/config.py` 설정을 읽는다.
2. `app/db/session.py`의 `create_engine()`과 `async_sessionmaker`로 작업 전용 세션을 만든다.
3. 필요한 HTTP 클라이언트를 열고 `app/modules/data_pipeline/pipelines/`의 회차 처리를 한 번 호출한다.
4. 결과를 정해진 형식으로 기록하고 클라이언트·세션·엔진을 닫는다.
5. 합의한 종료 상태로 프로세스를 종료한다. 무한 루프나 내장 스케줄러를 추가하지 않는다.

인자 이름·회차 결과·부분 성공 시 종료 코드·재실행 기준은 첫 수집 작업 구현 시 AWS 담당과 정한다. 성공·실패를 시험한 뒤에만 ECS/Scheduler에 등록한다. API의 `get_session()`이나 앱 lifespan을 재사용하지 않는다.

DB 마이그레이션은 기존 루트 `migrations/`와 Alembic 명령을 사용하며, 수집 실행 때 자동 적용하지 않는다.
