# 단발 수집 실행 진입점

## 저장 후 지도 공개

수집·정형 저장을 먼저 커밋하고 지도 공개는 별도 트랜잭션으로 처리한다. 최상위 `status`는 기존 수집/처리 결과이며, `publication.status`와 `publication.layers`가 공개 성공·실패·보류를 나타낸다. 저장 성공 후 공개 실패/보류라면 종료 코드 `2`를 반환한다. 기존 수집 실패 `1`·부분 처리 `2`·제공처 중단 `4`는 유지한다.

| 실행 | 공개 처리 |
| --- | --- |
| 서울/시영/전국 주차 수집, 도시데이터 주차 투영 | 주차 위치·이름·식별 상태가 달라질 때만 공개 지물 교체 |
| TOPIS 도로 기준 파일 가져오기 | 검증된 기준본 커밋 후 도로 지물·관측 공개 |
| 공식 장소 경계 가져오기 | 인구 관측 영역·관측 공개 |
| TOPIS 수집 | 회차 종료 후 도로 관측만 갱신 |
| 도시데이터 단일 수집 | 인구 관측만 갱신. 주차는 기존 별도 투영 명령 사용 |
| 도시데이터 전체 수집 | 주차 투영·공개 후 인구 관측을 회차당 한 번 갱신 |

관측 갱신은 기존 도로선/경계와 `geometry_version`을 유지한다. 공개된 기준본이 없거나 검증된 정형 기준본과 다르면 기준본과 관측을 같은 트랜잭션으로 복구한다. 정형 기준본 자체가 없을 때만 보류하며, 공개 SQL 실패는 이전 공개본을 유지한다. `python -m jobs.publish_map roads`처럼 해당 레이어(`roads`, `population`, `parking`)를 명시한 수동 재시도도 가능하다. 같은 자료를 재공개하면 중복 지물을 만들거나 공개 시각을 새로 쓰지 않는다.

스케줄러는 주차·TOPIS·CITYDATA의 수집 시작 전에 이전에 커밋된 자료의 공개를 확인한다. 수집 자식 프로세스가 시간 초과·취소·오류로 끝나거나 비정상 종료 코드를 반환하면 종료를 확인한 뒤 같은 작업 잠금을 유지하며 공개를 복구한다. 공개 오류는1초 후 한 번 더 시도하고 각 시도는120초로 제한한다. 부모 스케줄러까지 종료된 경우 다음 실행의 수집 전 복구를 사용한다. 이 과정은 외부 API를 다시 호출하지 않으며 수집 결과와 공개 결과는 따로 보고한다. 기존 수집 주기·실패 대기는 유지한다.

공개 실패는 이미 커밋한 수집 결과를 되돌리지 않으며 이전 공개본을 유지한다. 저장 후 프로세스가 종료된 경우도 같은 공개 명령으로 복구한다. 자동 재시도 큐나 스케줄 주기는 추가하지 않았다. S-DoT는 기존 정형 센서 저장까지만 처리하며 새 지도/API 레이어를 만들지 않는다.

## 수집 실행

데이터 처리 담당이 작성하고 AWS 담당이 실행 명령·종료 상태를 연결한다. API와 같은 코드·설정·DB 모델을 사용하되 별도 프로세스로 실행한다.

- `python -m jobs.collect_parking`: 서울 공영주차장 등록 기본정보 수집. `.env`의 `APP_SEOUL_API_KEY` 사용.
- `python -m jobs.collect_citydata --area "광화문·덕수궁"`: OA-21285 응답 전체를 장소별 최신 스냅샷으로 저장. 유동인구, 도로소통, 대중교통, 주차, 사고·통제, 따릉이, 날씨, 충전소, 행사, 상권 등 응답에 포함된 모든 섹션을 보존한다. `.env`의 `APP_SEOUL_CITYDATA_API_KEY` 사용.

Citydata는 요청 1회에 장소 1곳을 조회한다. 개별 장소 점검은 `collect_citydata`, 전체 수집은 `collect_citydata_all`을 사용한다. 전체 수집 후 `project_citydata_parking`이 저장된 도시데이터의 주차 정보를 반영한다. 원문 봉투 전체는 재현 근거로 보존하고, 실제 소비 경로는 인구·주차·도로 좌표 필드의 `citydata-selected-v1` 가공본을 사용한다. 미채택 섹션이나 새 필드가 자동으로 제품 API에 제공되는 것은 아니다.

`collect_citydata --area`에는 공식 장소명 또는 코드(예: `POI009`)를 넣는다. 공식 목록의 이름·코드 쌍을 응답과 대조한다. 일반/dotted 결과 코드와 실제 HTTP 수신 시각·결과 봉투를 보존하며, 잘못된 코드/장소의 JSON 응답도 실패 근거로 보관한다. 연결 실패나 JSON 해석 실패에는 복원한 원문을 만들지 않는다. `unit=section`, `scope=citydata_section_processing`은 인구 처리와 주차·도로 입력 준비의 세 항목 집계다. `sections.population`의 필드 품질/실제 쓰기/유지한 관측을 별도 확인한다. 주차의 실제 적재·중복·충돌은 후속 주차 투영 결과(`unit=row`)에 기록되며, 도로는 좌표 대조용이고 TOPIS 소통값으로 적재하지 않는다.

진입점 담당 순서:

1. 실행 인자와 `app/core/config.py` 설정을 읽는다.
2. `app/db/session.py`의 `create_engine()`으로 작업 전용 DB 연결을 만든다.
3. HTTP 클라이언트를 열고 `app/modules/data_pipeline/pipelines/`의 회차 처리를 호출한다.
4. 민감정보를 제외한 결과를 JSON 한 줄로 출력한다.
5. 클라이언트와 엔진을 닫고 성공/실패 종료 코드를 반환한다.

저장 작업은 수집 원문뿐 아니라 정규화 결과까지 확인한다. 정규화 실패 시 원문·실패 기록을 커밋한 후 실패를 알리며, 부분 처리도 성공으로 보고하지 않는다. 단발 명령의 종료 코드는 성공 `0`, 실패 `1`, 부분 처리 `2`다. 잠금으로 건너뛴 수집은 `3`, 인증·한도 문제로 중단한 TOPIS/CITYDATA 회차는 `4`를 사용한다.

모든 실행 모듈은 동기 `main()`에서 CLI 인자를 처리하고 비동기 `execute()`에서 자원 준비·결과 출력 후 정수 종료 코드를 반환한다. `jobs/runtime.py`가 JSON 한 줄 출력, 상태별 종료 코드, 실행 예외와 사용자 중단(`130`)을 공통 처리한다. 파이프라인은 처리 결과를 반환하며 직접 프로세스를 종료하지 않는다. 스케줄러는 개별 작업 코드와 실행 조건을 종합해 단발 실행의 성공 여부를 반환한다.

공식 자료 경로는 `REFERENCE_DATA`(`data/reference/`), 로컬 파일 경로는 `RAW_DATA`(`data/raw/`)를 사용하며 현재 작업 디렉터리에 의존하지 않는다. 기본 원문 저장소는 `data/raw/payloads`이며 Compose가 `data/raw/`를 컨테이너에 연결한다. 원문 저장 디렉터리는 저장 시 자동으로 생성된다. `data/`는 공식 XLSX·ZIP 입력 파일만 Git과 Docker 빌드에 포함한다. 모든 명령은 `--help`로 인자를 확인할 수 있다.

공통 스냅샷 저장은 `app.modules.data_pipeline.pipelines.snapshots.save_snapshot`을 호출한다. 저장 검증은 `tests/integration/`에서 실제 테이블과 원문 보관 파일을 확인한다.

`python -m jobs.collect_supplemental areas|sdot|cctv|parking`은 설정·자원을 준비하고 `pipelines/supplemental.py`를 호출한다. 외부 요청은 `collectors/supplemental.py`, 값 변환은 `normalizers/supplemental.py`(SGIS/CCTV)·`normalizers/sdot.py`(센서), 좌표 변환·서울 경계 포함 조회는 `SpatialRepository`가 담당한다. S-DoT·CCTV는 SGIS 서울 경계가 없으면 외부 API 호출 전에 실패한다. HTTP 대기 중 DB 트랜잭션은 열어두지 않는다.

SGIS는 `https://sgisapi.mods.go.kr/OpenAPI3/`를 사용한다. 행정동·서울 경계를 행별로 검사하고, 무효 Polygon/MultiPolygon은 유효한 면 도형으로 복구되고 상대 면적 변화가0.1% 이내일 때만 채택한다. 실패한 행은 원문·사유와 함께 기록하며 기존 정상 도형은 유지한다. 다른 정상 행의 저장은 계속한다.

전국 주차 시설·운영은 각각 다음 페이지를 기존 처리 보고서의 `pagination_progress`에 저장해 다음 실행에서 이어받는다. 현황은 매회1페이지부터 조회하고 기능별 최대5페이지·5,000행 상한을 유지한다. 진행 기록은 정형 저장과 같은 트랜잭션으로 커밋하므로 DB 실패 시 페이지를 건너뛰지 않는다. HTTP 실패 페이지는 다음 회차에서 재시도한다. 제공 총수보다 일찍 끝난 페이지는 다음 회차에도 동일한지 확인한 뒤 불일치 경고와 함께 새 스캔을 시작하며, 전체 수집 완료로 표시하지 않는다.

기존 `cctv --reuse-probe` 옵션은 `data/raw/its_probe.json`이 있을 때 요청 없이 파일과 수정 시각을 재사용한다. 이 파일은 공식 입력 파일이나 자동 수집의 선행 조건이 아니다.

DB 마이그레이션은 기존 루트 `migrations/`와 Alembic 명령으로 별도 적용한다. AWS 스케줄 연결은 수집 주기와 호출 한도를 합의한 뒤 구성한다.

## 자동 수집

서울시 공식 OA-21285 첨부파일(목록 seq=23)을 data/reference/seoul_areas.xlsx에 보관했다. jobs.collect_citydata_all은 이를 읽어 121개 공식 장소를 각각 요청한다. 인증키는 기존 APP_SEOUL_CITYDATA_API_KEY를 사용하며 키를 출력하지 않는다.

도시데이터·주차 명령은 실행 인자·설정·출력만 담당하며 실제 회차 처리는 `app/modules/data_pipeline/pipelines/`에 있다. 공식 장소 목록은 `collectors/citydata.py`에서 읽고, 시영주차 좌표 조회는 `ParkingRepository`, 유일 좌표 연결은 `normalizers/parking.py`에서 처리한다.

전체 수집의 마지막 JSON에서 `success`·`partial`·`failed`·`skipped`는 장소별 수집 건수이고 `parking_projection`은 주차 반영 결과다. 최상위 `status`는 수집·주차 투영 두 단계를 함께 판단한다. 공개 결과는 `publication`으로 분리하며 공개 실패/보류도 종료 코드에 반영한다. 어느 단계든 실패하면 실패, 전부 성공하면 성공, 전부 건너뛰면 건너뜀, 그 밖에는 부분 처리다.

CITYDATA의 공통 인증·한도 오류는 남은 장소 요청을 중단한다. 이때 `status=paused_provider_limit`, `cycle_complete=false`, `stop_reason`, `completed`, `remaining`으로 중단 지점을 알리고 이미 처리한 입력의 주차 투영·공개는 진행한다. 개별 장소의 입력 오류는 다른 장소 처리를 막지 않는다.

실행: `docker compose up -d citydata-collector`
중지: `docker compose stop citydata-collector`
단발 전체 수집: `docker compose run --rm --no-deps api python -m jobs.collect_citydata_all`

서비스 이름은 `citydata-collector`지만 실제로는 `jobs.scheduler`가 아래 작업을 함께 실행한다. 별도 수집 Compose 파일은 사용하지 않는다.

| 작업 | 기본 주기 | 선행 조건 |
| --- | --- | --- |
| 도시데이터 121장소 | 600초(10분) | 서울 도시데이터 키 |
| 주차 등록정보 | 86400초 | 서울시 키 |
| 시영주차장 | 600초(10분) | 시영주차장 키 또는 서울시 키 |
| SGIS 행정동·서울 경계 | 604800초 | SGIS 키·시크릿 |
| S-DoT | 600초 | S-DoT 키와 SGIS 서울 경계 |
| 전국 주차정보 | 3600초(1시간) | 공공데이터포털 키 |
| ITS CCTV 목록 | 자동 수집 비활성화 | 필요 시 `collect_supplemental cctv` 수동 실행 |
| TOPIS | 600초(10분), 전체 활성 도로 | TOPIS 키 또는 서울시 키와 정형 적재된 공식 도로 자료 |

성공·부분 처리의 주기는 회차 시작 기준이며 작업이 길어지면 완료 후 최소1초 대기한다. TOPIS 전체 수집이10분을 넘기면 완료 후 다음 회차를 시작하며 중복 실행하지 않는다. 실패는 완료 후 별도로 기다린다. SGIS·서울 주차·CITYDATA·시영은300초, S-DoT는600초, 전국 주차·TOPIS는3600초다. 인증·한도 중단 코드4는 최소3600초 대기한다. 키가 없으면 건너뛰고 선행 자료가 없으면 최대60초 뒤 재확인한다. 실제 값은 [scheduler.py](scheduler.py)의 `TASKS`에서 관리한다. 같은 작업의 개별 반복 실행과 스케줄러를 동시에 켜지 않는다.

TOPIS는 성공/부분 처리된 도로가 있으면 다른 도로의 호출 오류가 있어도 회차를 `partial`로 반환해 전체10분 주기를 유지한다. 네트워크·타임아웃·HTTP5xx 오류가 난 도로만0.5초·1초 대기 후 최대2회 추가 시도한다(총3회). 재시도도 동시8개·요청 시작 간격0.05초 제한을 공유하며 DB 저장은 최종 결과에 한 번 수행한다. 관측 없음·잘못된 응답·일반4xx는 즉시 재시도하지 않고, 인증/한도 오류는 신규 요청과 대기 중 재시도를 중단한다. `attempts`는 도로별 실제 호출 횟수, `retry_attempts`는 회차의 추가 호출 횟수이며 완료 도로 수에 중복 집계하지 않는다. 회차 전체 실패나 DB/실행 오류에는 기존1시간 대기를 유지한다.

첫 회차에는 선택·설정된 `areas`가 끝난 뒤 S-DoT, `parking`이 끝난 뒤 시영을 시작한다. 독립 작업은 병렬 실행하며 이후 주기는 각각 유지한다. `--once`는 각 작업의 결과를 마지막 JSON의 `results`에 보존하고 부분 처리는2, 전부 건너뜀은3, 제공처 중단은4로 반환한다. 실패/선행조건 대기는1이다. 복수 스케줄러 간 잠금은 실행 겹침만 막으므로 현재는 작업자1개를 사용한다. 원천 기준 시각과 수집 시각은 구분하며 Docker Desktop이 켜져 있어야 자동 수집이 동작한다.

서울 응답 본문의 `ERROR-500`·`ERROR-600`도 서버 오류로 분류해 같은 제한된 재시도를 적용한다. 서울 주차·CITYDATA 역시 HTTP 200으로 전달된 이 오류를 최대2회 추가 시도한다. 서울 등록·시영주차는 중간 페이지가 실패해도 받은 행을 저장하며, 불완전 목록에서 누락 시설은 비활성화하지 않는다.

선행 경계·도로 확인은 `ReferenceRepository.has_prerequisite()`로 정형 테이블과 적재 메타데이터를 조회한다. 원본 파일 전체를 열지 않으며, 마지막 정상 적재본에 연결된 활성 행이 있어야 실행한다. 실패한 재적재 후에는 기존 정상 자료를 사용할 수 있지만, 정상 빈 적재본이나 비활성 자료를 이전 행으로 대신하지 않는다. 이 조회 전환은 `TASKS`의 수집 주기·대상 수·실패 후 대기를 변경하지 않는다.

위치는 신규 항목 또는 실제 좌표 변경 때만 쓴다. 서울 등록·전국 시설·CITYDATA 주차는 응답에 좌표가 반복되어도 기존 좌표와 같으면 정형 위치 UPDATE에서 제외한다. 시영 현황은 기존 서울 등록정보의 위치를 사용한다. S-DoT 설치점·SGIS 경계·도로선·121장소 경계도 같은 도형의 재쓰기를 생략하고, 수신 근거·현황 등 다른 정보는 각 규칙대로 갱신한다. 공개 지도도 추가·변경·삭제된 지물만 반영한다. TOPIS 소통 수집은 도로선을 갱신하지 않으며 도로선·ID 매핑·121장소 경계의 가져오기는 수동 실행을 유지한다.

API 조회는 요청별 읽기 전용 스냅샷을 사용한다. 갱신 중에는 커밋 전 값을 읽고, 조회 도중 커밋돼도 응답 안에서 이전/새 값이 섞이지 않는다. 정형 저장과 지도 공개는 각각 기존 트랜잭션 단위를 유지하며, 전체 스케줄 회차를 하나의 트랜잭션으로 묶지는 않는다. [구현·동시성 검증](../tests/integration/test_read_snapshot_isolation.py).

## 시영주차장 및 TOPIS

시영주차장 `python -m jobs.collect_municipal_parking`: 원본 전체를 파일에 회차별 보존하고 `raw_payloads`에 참조를 기록하며 좌표가 유일하게 연결된 기록을 주변 조회에 적재. 개별 명령은 `--interval 600`으로 반복할 수 있으며 Compose 자동 수집은 위 공통 스케줄러를 사용한다.

TOPIS `python -m jobs.collect_topis --link 1220003800` (여러 --link 허용): XML을 해석한 응답과 도로별 결과를 회차 파일 하나로 저장. 전체 도로 반복 호출 아님. TOPIS 서비스 링크별 관측값이며 도시데이터의 표준 링크 ID와 직접 연결하지 않는다.

회차 파일 `entries`의 `processing`에서 값 품질과 `updated`를 확인한다. 속도/여행시간 중 하나만 유효하면 부분 처리이며, 둘 다 결측/무효면 실패로 기록하고 마지막 채택값·원래 시각을 유지한다. 정상 0은 유효하다. 일부 결측을 이전 값으로 채우지 않으며, 수신 순서가 역행한 응답은 `traffic_time_guard`로 보류한다. 값이 정상이어도 TOPIS의 원천 관측 시각은 미제공 상태다. 도로별 상세 결과는 회차 파일의 `entries`에 묶고 별도 도로별 로그·보고서를 만들지 않는다.

`collect_topis`와 `collect_topis_network`는 설정·HTTP/DB 자원·출력·종료 코드를 맡고, 서로를 가져오지 않는다. 공통 수집은 `pipelines/topis.py`, 대상 선정·회차 결과 규칙은 `pipelines/topis_rules.py`, TOPIS 요청은 기존 `collectors/topis.py`에서 처리한다. `collect_topis_network`의 명시적 반복 대기만 실행 파일에 남는다.

자동 수집은 `--all`로 검증된 전체 활성 도로를 선택하며 `--max-links`로 제한하지 않는다. 격리·비활성 도로는 제외한다. 소량 점검용 `--scheduled-batch --max-links N` 옵션은 수동 실행에서 사용할 수 있다. 요청 중 한도·인증 오류가 발생하면 새 요청을 중단하고 종료 코드 `4`를 반환하며, 명시적 반복은 최소1시간 뒤 재개한다. 관측 없음만 발생한 회차는 부분 처리 `2`, 그 외 실패는 `1`이다. 동시 요청 최대8개·요청 시작 최소0.05초 간격과 기존 실패 대기는 유지한다.

회차 마지막 JSON은 기존 `cycle_complete`·`target`·`counts`에 최종 `status`를 함께 출력한다. `cycle_complete`는 선택한 대상 처리가 끝났는지를 뜻하며 전부 성공했다는 의미는 아니다. `completed`·`remaining`·`retry_attempts`·실패 도로 목록을 함께 기록한다. 수집 중에는 같은 회차 행의 진행 수량만 갱신한다.

회차당 `collection_runs` 1행과 통합 원문·결과 파일 1개를 남기며, TOPIS 로그는 최신20회만 보관한다. 시작한 회차도20회에 포함한다. 초과 로그·불필요한 원문과 보고서는 오래된 것부터 정리한다. 현재 정형값·지도·다른 자료가 참조하는 원문은 로그와 분리해 유지하며 마지막 실제 수신 시각을 바꾸지 않는다. 도로별 최근 상태는 `road_traffic_attempt_latest`의1행을 갱신한다. 수집 중에는50건 또는1초마다 임시 저장하고 종료 시 통합한다. 중단된 회차는 다음 수집 전·스케줄러 복구에서 통합한다. DB 삭제가 커밋된 뒤 파일을 삭제하며 실패한 파일 정리는 다음 회차에 재시도한다. 기존 DB에는0011 적용이 필요하다. [보관 정책·검증](../tests/integration/test_topis_retention.py).

TOPIS 전체·자동 순환은 도로 ID·시도 기록을 DB에서 직접 조회한다. 과거 장소 지정 수집 옵션은 제거했으며, 호출할 도로를 고르기 위해 도시데이터 원문이나 표준 ID 매핑을 읽지 않는다. 도시데이터 자체의 장소별 수집, 주차 재처리·실시간 주차 정보와 API 응답 처리는 유지한다.

## 인구·센서 전처리 결과

영역 인구는 범위·등급·대체 여부·시각을 각각 검사하며 `population_quality`에 결과를 반환한다. 수치는 유효해도 메타데이터가 없으면 partial이고 미확인 필드는 NULL로 유지한다. 인구가 없거나 범위/시각이 무효이면 원문과 실패 사유를 보존하며 기존 값을 지우지 않는다. accepted=1은 해당 응답의 정형 반영을 뜻하고 필드가 모두 완전하다는 의미는 아니다.

S-DoT는 KST 현재 시간대와 직전 2개 시간대만 조회한다. 합계 최대10페이지·1만 행이며 기존 재시도 포함 최대30회 HTTP 시도다. 시간대별 총수·실제 수신 시각·중복·빈 페이지/실패를 기록하고 시간 필터 위반은 채택하지 않는다. 측정 시각·DATE로 직접 최신값을 선택한다. `query_complete`는 선택 시간대의 응답 총수와 받은 행의 일치이며 전 센서 최신값 확보나 요청 간 고정 스냅샷을 뜻하지 않는다.

`records`는 서울 경계 필터 후 설치 위치 수다. `observation_summary.with_count`는 이번 입력에 값이 있는 센서 수, `usable_observations`는 입력의 시각 근거까지 검증된 수이며 TTL 판단은 포함하지 않는다. 원천 행 품질 `observation_quality`는 서울 공간 필터 전의 observation_row 단위다. `accepted`는 설치정보·최근 시도를 기록한 센서 수이고, 실제 유효 관측 갱신 수는 `storage.observations_written`이다. 이번 조회에 없는 센서는 미관측으로 남기고 0명/고장으로 바꾸지 않는다. B10은 원본 XLSX·페이지 전체 응답·가공본·보고서를 보관하고 설치 기준정보/마지막 유효 관측/최근 시도를 두 정형 테이블에 저장한다. 수신 시각을 모르는 과거 표본은 값이 있어도 시도에만 보존한다. 실행 전 DB를 정식 0010까지 적용해야 한다.

## 공식 도로선·ID 매핑

`python -m jobs.import_topis_geometry`는 data/reference의 공식 도로선·표준 매핑 XLSX를 검증한다. 기본 파일은 해시가 확인된 2025/2025-03-06 자료에만 해당 버전을 자동 적용한다. 파일 내용이 달라지면 버전을 명시해야 한다.
`python -m jobs.import_place_boundaries`는 공식 121장소 SHP 경계를 내부 링까지 보존해 적재한다.

현재 동봉된 보간점 파일은 링크 `1000020300`의 정점 순서가 빠져 있다. 이 링크의 제외를 검토한 후 `python -m jobs.import_topis_geometry --allow-excluded-link 1000020300`으로 나머지5,092개의 공간 검증을 진행한다. 제외 목록을 지정하지 않거나 실제 제외 목록과 다르면 `unreviewed_reference_exclusions`로 보류한다. 공간 대조 후 문제가 있는 서비스 링크는 `quarantined_service_ids`로 격리하므로 실제 활성·수집·공개 개수는 더 적을 수 있다. 새 파일은 `--vertices-file`·`--mapping-file`과 각 `--vertices-version`·`--mapping-version`을 사용한다. 확인된 날짜만 `--vertices-date`·`--mapping-date`로 전달하며 연도만으로 날짜를 만들지 않는다.

전체 공식 파일이라는 전제로 교체하며, 부분 추출물은 `--partial`로 기록만 남긴다. 빈 입력·부분 입력·미검토 제외·미연결 매핑·공간 검증 실패는 기존 기준본을 유지한다. 정상 교체는 도로 활성 범위·현행 표준 매핑·행정동 연결을 한 트랜잭션으로 바꾸고 빠진 도로의 과거 소통 관측은 보존한다. 원본 XLSX 두 개·파일별 버전/날짜/해시·가공본·처리 보고서를 함께 보관한다.

결과의 `processing.updated`는 실제 기준본 전환 여부다. 검토한 제외나 미확인/모호한 매핑 순번이 있으면 적용돼도 `status=partial`(종료 코드 2)이며 품질 목록을 확인한다. 순번 없는 관계는 `sequence_status=unknown`, 같은 순번의 여러 표준 링크는 `ambiguous`로 보존한다. 저장용 순번 0을 실제 진행 순서로 사용하지 않는다. 정형 저장 커밋 후 도로 공개본까지 자동 갱신한다. 실패하면 기존 공개본을 유지하고 `publish_map roads`로 재시도한다.

두 명령은 파일 경로·설정·자원·출력만 맡으며, 가져오기 흐름은 `pipelines/official_files.py`, 파일 해석은 `collectors/official_files.py`, 값 검증은 `normalizers/official_files.py`, 공간 SQL은 `SpatialRepository`에 있다. TOPIS 공간 검증 결과는 `spatial_validation`에 비교 쌍별 지표·상태·좌표 순서와 입력 payload/장소/행 근거를 기록한다. 자료 없음(`missing_spatial_reference`), 공식 대응 없음(`missing_spatial_correspondence`), 자료 부족(`insufficient_spatial_reference`), 같은 ID의 좌표 충돌(`conflicting_spatial_reference`), 잘못된 좌표(`invalid_spatial_reference`), 대응 불일치(`road_geometry_mismatch`), 공간 계산 실패(`spatial_validation_failed`)를 구분하고 종료 코드 `1`을 반환한다. 이 경우 기존 도로선은 갱신하지 않는다. 검증 후 정형 저장이 실패하면 공통 저장 흐름에서 원문·실패 회차를 보존한다.

`python -m jobs.collect_topis_network --all`은 공식 도로 전체를 한 번 수집한다. `--all --scheduled-batch --max-links 20`은 미시도·오래된 도로부터 최대 20개만 수집한다. 기본은 단발이며 반복은 `--interval`로 명시한다. 공식 자료의 출처·버전·연결 규칙은 아래 [공식 입력 자료](#공식-입력-자료)를 참고한다.


DB head 0009에서 수집 원문은 불변 파일로 보존하고 `raw_payloads`에는 경로·해시·크기를 기록한다. 핵심 값과 제외 사유는 정형 테이블에 적재한다. API·작업·마이그레이션의 `APP_PAYLOAD_STORAGE_DIR`는 같은 저장소여야 한다.
`project_citydata_parking`은 새 수집으로 기록하지 않으며 원본 payload와 수신 시각을 유지한다.
주차 반영 도중 정규화가 실패하면 해당 반영의 DB 쓰기를 되돌리고 원본 연결과 실패 회차를 보존한다. 단독 실행도 부분 처리·실패를 종료 코드에 반영한다.
`publish_map`은 정형 테이블을 읽어 공개본을 만든다. 자세한 적용 순서는
[백엔드 README의 DB 변경 절차](../README.md#새-기능을-추가할-때)를 참고한다.
공개 완료 시 `{"status":"success","layer":"roads","features":123}` 형식의 JSON을 출력하고 종료 코드 `0`을 반환한다. `features`는 해당 실행이 공개한 개수다.

## 공식 입력 자료

`data/reference/`에는 수집 대상과 공간 기준정보를 만드는 고정 입력 파일을 보관한다. 기존 `jobs/data/`에서 내용 변경 없이 옮긴 자료이며 Git으로 공유하고 Docker 이미지에 포함한다. 아래 기준일은 기존 파일명·구현 기록에 따른다. 갱신 시 출처·기준일과 실행 경로를 함께 갱신한다.

| 파일 | 내용·출처 | 사용하는 작업 |
| --- | --- | --- |
| `seoul_areas.xlsx` | OA-21285 공식 121장소 목록, 기존 기록의 첨부 seq=23 | `collect_citydata_all` |
| `citydata_places_official.zip` | 기존 저장소의 공식 121장소 경계 SHP 묶음 | `import_place_boundaries` |
| `sdot_locations_20251113.xlsx` | 기존 저장소의 S-DoT 설치 위치 목록, 파일명 기준 2025-11-13 | `collect_supplemental sdot` |
| `topis_vertices_2025.xlsx` | OA-15060 서비스링크 보간점, 2025 자료 | `import_topis_geometry` |
| `topis_standard_mapping_20250306.xlsx` | OA-15061 표준링크·서비스링크 매핑, 2025-03-06 자료 | `import_topis_geometry` |

- TOPIS 속도·통행시간은 서비스 링크 전체의 관측값이다. 도시데이터의 표준 링크와는 공식 매핑으로 연결하며 비슷한 번호나 인접 위치로 ID를 추정하지 않는다.
- 도로 보간점의 `GRS80TM` 헤더는 기존 EPSG:5181 해석으로 WGS84(4326)에 변환한다. TOPIS 공식 지도 구현의 EPSG:5181 해석을 확인했다. 정점 순서 누락·충돌과 공식 매핑에 따른 CITYDATA 선형을 함께 검증하며 `provider_epsg_confirmed=true`와 공식 코드 근거를 기록한다. 모든 도로 형상·방향 검증 완료를 뜻하지 않는다.
- 짧은 선의 양 끝을 긴 선에 투영한 대응 구간을 비교한다. 포함 비율90% 이상, 대응 구간/짧은 선 길이비0.8~1.25, 10m 이하로 분할한 선의 Hausdorff 거리30m 이하를 내부 기준으로 사용한다. 전체 일치 쌍90% 이상·독립 서비스 ID/표준 ID/형상 각각10개 이상의 근거가 있으면 부분 겹침은 경고로, 분리·교차·형상 불일치 등은 해당 서비스 링크 격리로 처리한다. 격리 도형·관계·판정은 보고서에 남기고 활성 도로·현행 매핑·수집·공개에서 제외한다. 광범위 불일치, 좌표 충돌/무효, 검증 자료 부족은 전체 교체를 보류한다.
- 이 수치는 제공처의 정확도 보증이 아니다. 보고서의 미검증 도로 수와 표본 경계 범위를 함께 확인한다. 배열 역순은 기록하지만 통행 방향을 증명하지 않으며, 일부 표본 통과를 전체 서울 도로 검증으로 표시하지 않는다.
- 장소 경계는 121개 고유 장소와 좌표계를 확인하고 내부 링도 보존한다. S-DoT 위치와 최신 관측은 센서 ID로 연결한다.

팀과 공유할 작은 검증 표본은 `tests/fixtures/`에 출처·시각·가공 내용을 기록해서 추가한다. 실행 중 생성되는 원문과 로컬 백업은 Git·Docker 빌드에서 제외한다.

전국 주차(`collect_supplemental parking`)는 기능별 수집 상태와 정형 처리 결과를 함께 출력한다. 기본·추가 요금 시간은 사용자 확인에 따라 분으로 저장한다. 정상 빈자리 수는 관측 시각 미제공만으로 부분 실패로 처리하지 않으며, 수신 시각 기준 1시간 활용 정책을 따른다. 값 오류·미연결 관리 ID 등 실제 제한은 `partial`로 보고한다. `accepted`는 원천 행의 정형 반영 수이며 현재 사용 가능한 빈자리 수가 아니다. 페이지별 원문과 실제 수신 시각은 보존하고 기능별 5천 행 제한을 전체 기준본으로 사용하지 않는다. B04/B05 모델은 정식 0010에 포함돼 있으며 기존 0009 DB는 전환 후 실행한다.

전국 주차 자동 수집 간격은 1시간이다. 내부 소비자는 `ParkingRepository.availability()`로 최신 활용값을 읽는다. 전국 빈자리는 저장된 최근 수신 수량을 이용하며, `time_basis=received_at`, `observed_at=None`으로 실제 측정 시각과 구분한다. 수신부터 1시간까지 허용하고 그 이후에는 `usable=false`, `available_spaces=None`, `STALE_DATA`다. 범위 충돌·무효 수량·미래 수신 시각은 허용하지 않는다. 제공처가 실제로 1시간마다 갱신한다는 뜻은 아니며 기존 외부 API의 빈자리 제공 기능을 새로 구현한 것은 아니다.

시영·CITYDATA 빈자리는 실제 `observed_at`부터1시간까지 허용하며 미래·미확인·만료 시각은 활용하지 않는다. 최신 응답이 명시적으로 미제공이면 `NOT_PROVIDED`로 수량을 반환하지 않는다. 마지막 유효 관측의 숫자·근거는 DB에 유지하며, DB의 유효 관측 보존 플래그와 현재 조회의 `usable`은 구분한다.

SGIS 행정동 경계 변경·활성 목록 교체와 도로↔행정동 관계 재계산은 같은 트랜잭션에서 처리한다. 수집한 전체 구 목록과 각 구의 동 목록이 비어 있지 않고 모든 요청·도형 검증을 통과한 완전한 기준본만 누락 동을 비활성화한다. 부분·빈·중복 입력은 누락 항목을 삭제하지 않으며 같은 기준본을 반복 적재하면 관계도 다시 쓰지 않는다.

도시데이터 주차 투영의 `section_inputs`에는 사용한 원문/가공본·회차·실제 수신 시각과 마지막 시도 상태가 남는다. 최신 주차 섹션이 누락/무효면 이전 사용 가능한 입력을 명시적으로 재사용하고 부분 처리한다. 정상 빈 목록은 최신 빈 결과로 유지하며 과거의 비어 있지 않은 목록으로 대신하지 않는다. 수집 회차 안에서 사용한 자료는 `current_cycle`, 수동 재처리는 null로 구분한다. 주차 누락·빈 목록만으로 기존 시설을 비활성화하지 않는다.
